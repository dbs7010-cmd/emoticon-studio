# 앱 전체 개선 진단 — 2026-09-27

## 범위와 판단 기준

홈, 전체 작업, 표현 가이드, 세트 보드, 그리기, 색상·브러시·레이어, 움직이기, 내보내기, 설정·PRO 흐름을 현재 소스와 검사 코드, 첨부 화면으로 검토했다. 첨부된 이전 작업 기록은 참고 자료로만 사용했다.

실기기 전체 화면을 새로 조작한 검수는 아니다. 아래에서 **확인**은 소스/첨부 화면으로 확인한 동작, **제안**은 제품 개선안, **검증 필요**는 실기기에서 판단할 사항이다. 현재 수정 중인 코드와 기존 앱에 남은 문제를 구분한다.

## 총평

브러시·레이어·참고·움직임·파일 검사 등 기능은 이미 많다. 우선순위는 기능 수를 늘리는 것보다 **버튼 이름과 결과를 일치시키고, 작업을 안전하게 보존하며, 제작부터 파일 전달까지 막힘없이 이어 주는 것**이다. 편집기의 화면 밀도와 작은 글자도 함께 정리해야 한다.

## 2. 작품 보존과 작업 관리

### 작품 백업·복원 — 높은 우선순위, 기능 제안

현재 저장소는 앱 문서 디렉터리에 JSON 사본 두 개를 번갈아 저장한다. 쓰기 실패에 대비한 내부 복구 구조는 있다. 하지만 설정에 사용자가 작품 전체를 백업하고 다시 불러오는 흐름은 없다. 문의용 JSON 공유는 이미지와 편집 정보를 함께 복원하는 작품 백업과 다르다.

- 세트별 원본 백업: 레이어 이미지, 문구, 움직임, 참고, 설정을 한 묶음에 포함.
- 가져오기 전 검사, 동일 세트 충돌 처리, 복원 결과 안내.
- 앱 삭제·기기 변경 전에 무엇을 보관해야 하는지 설명.
- 클라우드 연동보다 먼저 파일 기반 백업·복원을 완성할 것.

근거: src/services/storage.ts:5, 31, 101; App.tsx:1306.

### 삭제 복구 — 높은 우선순위, 기능 제안

세트 삭제는 확인창 뒤 목록에서 바로 제거되고 UI는 되돌릴 수 없다고 안내한다. 휴지통 또는 일정 기간 복구 가능한 삭제가 필요하다. 원본 파일 정리 정책과 함께 설계해야 한다.

근거: App.tsx:331, 1265.

### 이름 변경과 세트 관리 — 구성 개선

‘세트 관리’에는 삭제가 있고 이름 변경은 ‘캐릭터 기준 · 세트 이름’으로 들어가야 한다. 관리하려는 항목이 두 군데로 나뉜다.

- 세트 관리에 이름 변경·복제·백업·삭제를 모은다.
- 캐릭터 기준에는 그림과 캐릭터 설정만 둔다.
- 전체 작업 목록에 이름 검색, 최근 수정/이름 정렬, 작업 중/완성 필터를 제공한다. 현재는 최근 수정순 전체 목록이다.

근거: App.tsx:537, 589, 849, 1261, 1394.

## 3. 처음 시작하는 사람의 흐름

### 표현 가이드의 적용 대상 — 확인된 동작, 개선 제안

표현을 골라 시작하면 가장 최근 세트의 다음 미완성 칸을 자동으로 연다. 사용자가 다른 세트에 넣으려는 경우 목적지 선택이 부족하다.

- 행동 버튼 근처에 ‘어느 세트의 몇 번 칸에 넣는지’를 표시.
- 최근 세트를 기본으로 제안하되 다른 세트/새 세트를 선택할 수 있게 한다.
- 참고로 보기와 밑그림으로 넣기의 차이를 실제 작은 미리보기로 설명한다.

근거: App.tsx:297–314.

### 도움말 — 기능 제안

설정에 다시 찾아볼 수 있는 사용 방법이 없다. 일회성 힌트만으로는 재탭 설정, 두 손가락 확대, 참고의 출력 제외, 전체/부분 움직임 차이를 다시 확인하기 어렵다.

긴 온보딩 대신 첫 사용 시 짧은 문맥 안내를 제공하고, 설정에서 같은 내용을 다시 볼 수 있게 한다.

근거: App.tsx:1306; painter.tsx의 zoomHintShown, guideTip 관련 흐름.

## 4. 그리기 화면의 디자인과 조작

### 공간 배분 — 확인 + 디자인 제안

왼쪽 조절대는 72dp, 캔버스 여백은 좌우 합 20dp를 사용한다. 폭 320dp에서는 정사각 캔버스 한 변이 최대 228dp다. 조절대가 화면 폭의 22.5%를 차지한다. 첨부의 서로 다른 높이 화면을 같은 크기로 키워 보이게 만드는 것과 실제 작업 영역 개선은 구분해야 한다.

- 기본 편집 모드와 캔버스 집중 모드를 검토한다.
- 집중 모드에서는 조절대를 접고 필요할 때 굵기·불투명도를 연다.
- 확대/100% 복귀의 발견 가능성을 높인다.
- 좌우 손잡이 배치는 실사용 후 결정한다. 단순 폭 축소로 터치 영역을 줄이지 않는다.

근거: src/painter/painter.tsx RAIL_W, CANVAS_GAP, 캔버스 영역.

### 시각적 위계 — 디자인 제안

모드 탭, 브러시, 도구가 각각 선택 배경과 밑줄을 사용해 주목 지점이 많다. 이번 수정에서는 하단 브러시·도구의 중복 밑줄을 제거했다. 전체 앱에서는 다음 규칙으로 정리하는 편이 좋다.

- 그리기/움직이기: 탭의 밑줄.
- 선택 도구: 옅은 배경과 명확한 글자.
- 주요 실행: 노란 채움 버튼.
- 패널 열림: 도구 선택과 구분되는 표시.

움직임 카드 등 다른 화면에도 같은 역할별 규칙을 적용할 필요가 있다.

### 작은 글자와 터치 — 확인 + 실기기 검증 필요

참고·레이어·문구는 10dp, 색 추출·색 저장은 9dp 글자를 사용한다. 수치와 메뉴를 식별하기 어려울 수 있다. 폭 380dp를 기준으로 되돌리기 위치도 바뀐다.

- 필수 도구 이름과 수치는 가독성을 우선해 키우고 배치로 공간을 확보한다.
- 화면 폭에 따라 기능 위치를 옮기는 규칙은 최소화한다.
- 큰 글자, 긴 세트 이름, Android 탐색 버튼/제스처 모드에서 실제 잘림과 터치 간섭을 검사한다.
- 조절기 라벨·터치 영역 폭은 이번 수정에서 명시했다.

근거: painter.tsx:236, undoInModeRow, 보조 도구 줄, ColorPanel.

## 5. 움직임 제작

### ‘없음’의 범위 — 확인된 혼동

‘움직임 없음’을 선택해도 부분 움직임이나 두 모습 효과는 남는다. 코드상 의도된 동작이지만 화면의 ‘없음’은 전체 효과가 꺼진 것으로 읽힌다.

- ‘전체 움직임 없음’처럼 범위를 이름에 드러낸다.
- 별도 ‘모든 움직임 끄기’를 제공하고, 전체/부분/두 모습의 적용 상태를 요약한다.

근거: src/painter/motion-panel.tsx:133–138, 165.

### 초보자 접근과 결과 확인 — 기능 제안

부분 움직임은 레이어 구조를 이해해야 한다. ‘움직일 부분 선택 → 방향/중심점 → 미리보기’의 짧은 흐름을 제공하는 것이 좋다. 보관한 움직임은 기존 기능을 유지하면서 이름 변경과 결과 미리보기를 보강한다.

성능은 별도 계측이 필요하다. 효과가 여러 개일 때, 30초 이상 재생할 때, 저사양 기기에서 조절할 때의 프레임 유지와 발열을 확인해야 한다. 현재 코드만으로 부드러움을 보장할 수 없다.

## 6. 내보내기 완료 경험

### 진행·취소·실패 복구 — 확인 + 기능 제안

프레임 생성은 칸별 순차 작업인데 사용자는 ‘파일 묶음 만드는 중…’이라는 상태만 본다. 한 칸이 실패하면 나머지는 계속 처리한다.

- ‘8/24칸 처리 중’처럼 실제 진행 수를 표시.
- 안전한 취소와 실패한 칸만 다시 만들기 제공.
- 생성 결과, 누락 칸, 다음 행동을 결과 화면에 유지.

근거: App.tsx:496–525.

### 파일 전달과 제출 안내 — 구성 개선

현재 결과의 주 행동은 공유와 다시 공유다. 공유 가능 여부와 별개로 사용자가 파일을 다시 찾고, 무엇을 전달했는지 확인하는 흐름을 강화해야 한다.

- 사용자 선택 위치로 저장하는 흐름과 내보내기 기록을 검토.
- 외부 도구에서 마무리해야 하는 칸은 파일 생성 전부터 알린다.
- ‘작업 파일 묶음 생성’과 ‘제출 준비 완료’를 명확히 구분한다.
- 현재 안내하는 외부 도구 및 제출 규격의 최신성은 이번 진단에서 검증하지 않았다.

근거: App.tsx:510–532, 1090–1134.

## 7. 품질과 유지보수

### 실제 화면 검증 — 높은 우선순위

현재 화면 매트릭스는 React 노드와 스타일 수치 검사다. 네이티브 폰트, WebView 합성, 키보드, 터치와 드래그를 실제 픽셀로 검증하지 않는다. 첨부처럼 ‘검사 통과’와 ‘사용하기 좋은 화면’ 사이의 차이가 다시 생길 수 있다.

출시 판단에는 다음 실제 흐름을 포함해야 한다.

1. 새 세트 → 그리기 → 지우개 → 브러시 복귀 → 색 선택 → 저장.
2. 문구 입력 → 키보드 닫기 → 앱을 나갔다 돌아오기 → 재실행 후 복원.
3. 움직임 적용 → 여러 칸 처리 → 파일 생성 → 압축 내용 확인.
4. 내보내기 오류 칸 수정 → 원래 검수 화면 복귀.
5. 작은 화면/큰 글자/저사양 기기에서 동일 흐름 반복.

### 상태 관리와 화면 분리 — 기술 제안

App.tsx에는 여러 화면과 저장·결제·내보내기 상태가 함께 있고, Painter에도 패널 상태와 입력·저장 로직이 모여 있다. 서로 영향을 주는 변경을 찾기 어렵다.

전체 재작성보다 세트 관리, 내보내기, 편집기 패널부터 분리하고, 저장/이동/복귀의 상태 전이를 명확히 하는 편이 안전하다. 사용자 동작을 검증하는 테스트를 유지하면서 구조를 나눈다.

### 유지할 강점

자동저장의 사본 교대와 쓰기 검증, 참고의 최종 출력 제외, 무료 제작 흐름, 구매 전 PRO 안내, 파일 검사와 문제 칸 진입, 즐겨찾기·움직임 재사용은 보존할 가치가 있다. 기능이 없다고 가정하고 중복 구현하지 않는다.

## 권장 진행 순서

1. **동작 신뢰성:** 저장 의미, 내보내기 복귀, 형식 안내, 색상 패널, 브러시 복귀.
2. **작품 보호:** 백업·복원, 삭제 복구.
3. **핵심 편의성:** 세트 관리 통합, 목적지 선택, 검색·정렬, 내보내기 진행/재시도.
4. **디자인 정리:** 편집기 공간 배분, 글자 크기, 선택 표시, 도구 위치, 패널 공통 규칙.
5. **실기기 검수 후 확장:** 집중 모드, 부분 움직임 안내, 재사용·미리보기 개선.

## 이번 작업의 수정 상태

사용자가 전체 진단 보고를 요청하기 전에 색상 패널 공간·스크롤, 조절기 폭, 중복 밑줄, 지우개에서 현재 브러시로 복귀하는 동작을 수정했다. 파일은 작업 디렉터리에 있으며 커밋·APK 배포는 하지 않았다.

타입 검사 및 색상·뷰포트·디자인·구조 검사 통과 로그가 있다. 전체 검사 실행은 로컬 실행 환경 변경으로 종료 확인이 끊겨 남은 검사를 별도로 실행했다. 실기기 검수와 새 APK 검증은 수행하지 않았다. 로컬 HTML의 브라우저 열기도 URL 정책으로 차단되어 새 픽셀 화면 검수 근거로 사용하지 않았다.
