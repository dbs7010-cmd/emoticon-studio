# 45.14 — UI 8자리 제작 규격 (2026-09-21)

원본은 `src/design/asset-slots.ts` 다. 이 문서는 **그 값을 제작자에게 넘길 수 있게 풀어 쓴 것**이고, 둘이 다르면 코드가 맞다.
새 에셋을 만들지 않았고 UI 도 바꾸지 않았다. **아직 실제 기기 화면에서 본 적이 없다** — 아래 크기·여백은 코드 기준이다(UI-SHELL-LOCK 선언 아님).

## 공통 규칙
- 8자리 중 **6자리는 `AssetSlot` 공용 컴포넌트**가 그린다(`src/components/ui.tsx:170`). 맞춤은 `resizeMode="contain"` — **잘리지 않는다.** 비율이 다르면 잘리는 대신 여백이 생겨 작아 보인다.
- 예외 두 곳: `referencePoseThumbnail` 은 `resizeMode="cover"` + `overflow:hidden` 이라 **비율이 다르면 가장자리가 잘린다**. `proFeatureArtwork` 는 `AssetSlot` 을 쓰지 않고 86×86 `contain` 두 장으로 직접 그린다.
- 글자는 **앱이 그린다.** 그림에 글자를 구워 넣지 않는다(다국어·줄바꿈·접근성 때문).
- 넣는 방법: `src/design/asset-slots.ts` 의 그 자리 `source` 를 `require('../../assets/...')` 로 바꾼다. 레이아웃·비율은 건드리지 않는다.
- `dp` 는 화면 크기 단위다. 권장 원본은 @3x 기준(예: 112dp → 336px). 마스터는 더 크게 그려 두고 줄여 쓴다.

## 자리별 규격

### 1. `homeHeroArtwork` — 홈 첫 화면의 주인공
- 화면: 홈 › 창작 표면 오른쪽 위 (`App.tsx:636`)
- 역할: 앱을 열자마자 보이는 첫인상. 표면의 노란 원 위에 캐릭터가 앉아 있는 그림.
- 표시 크기: 화면폭 < 380dp → **96×96dp**, 그 외 **112×112dp** (표면 오른쪽 14 · 위 16 위치)
- 권장 원본: 336px(@3x) · 224 · 112 / 마스터 1024
- 비율·형식: **1:1 · PNG · 투명 배경 필수**
- 맞춤/잘림: contain — 잘리지 않음
- 안전 영역: 주 피사체는 칸의 오른쪽 79% × 위쪽 89% 안(왼쪽 21% · 아래 11% 는 비운다 — 제목과 행동 줄이 지나간다)
- 앱이 따로 그리는 글자: '나만의 이모티콘 작업실', '오늘의 표정을 그려 볼까요?', 버튼 두 개
- 현재: **없음**(도형 자리표시) · 우선순위 **P1**(첫인상 + 스토어 스크린샷에 함께 찍힌다)

### 2. `homeEmptyArtwork` — 세트가 하나도 없을 때
- 화면: 홈 › 점선 상자 안 (`App.tsx:648`), 세트가 0개일 때만
- 역할: "여기에 만든 세트가 모인다"를 그림으로 한 번 말해 주는 자리
- 표시 크기: **120×90dp**
- 권장 원본: 360×270(@3x) · 240×180 · 120×90 / 마스터 1280×960
- 비율·형식: **4:3 · PNG · 투명 배경**
- 맞춤/잘림: contain — 잘리지 않음 · 안전 영역: 가운데 80%
- 앱이 따로 그리는 글자: '첫 이모티콘 세트를 만들어 보세요' / '만든 세트가 여기에 모여요'
- 현재: **없음** · 우선순위 **P3** — 설치 직후 한 번만 보이고, 지금 자리표시 도형과 글자 두 줄로도 뜻이 통한다. **없어도 되는 자리**다.

### 3. `noticeArtwork` — 공식 공지 카드의 작은 그림
- 화면: 홈 › 공지 배너 왼쪽 (`App.tsx:655`). **지금은 `HOME_NOTICE.enabled = false` 라 화면에 아예 없다.**
- 역할: 공모전·이벤트 소식 줄임 표시
- 표시 크기: **44×44dp** · 권장 원본 132(@3x) · 88 · 44 / 마스터 512
- 비율·형식: **1:1 · PNG · 투명 배경** · contain(잘리지 않음) · 안전 영역 가운데 76%
- 앱이 따로 그리는 글자: 공지 제목 · 한 줄 설명 · 넘어가기 화살표(링크가 있을 때만)
- 현재: **없음** · 우선순위 **P3(보류)** — 공지 기능을 켜기로 결정할 때 함께 만든다. 지금 만들면 쓰이지 않는다.

### 4. `referencePoseThumbnail` — 기본 레퍼런스(관절 인형) 썸네일
- 화면: 그리기 › 참고 › 기본 레퍼런스 4열 격자 (`painter.tsx:1142·1175`). 지금은 `BUILTIN_REFERENCES.ready = false` 라 누를 수 없는 자리표시.
- 역할: "어떻게 그릴까?" — 고르면 캔버스에 옅게 깔리는 자세 참고
- 표시 크기(반응형): 칸 폭 = floor((격자 폭 − 24 − 8×3) / 4), 높이 = 폭 × 4/3 → 360dp 화면 **78×104dp** · 384dp **84×112** · 412dp **91×121**
- 권장 원본: 썸네일 192×255 + **캔버스에 깔 투명 원본 1080×1440**(두 벌)
- 비율·형식: **3:4 · PNG · 썸네일은 불투명 바탕 허용, 캔버스용 원본은 투명**
- 맞춤/잘림: **cover — 3:4 가 아니면 가장자리가 잘린다.** 안전 영역: 위아래 6% · 좌우 10%, 발끝은 94% 선
- 앱이 따로 그리는 글자: 분류 칩(포즈·표정·손동작·소품·효과), 아래 안내 '관절 인형 그림은 준비 중이에요'
- 현재: **없음** · 우선순위 **P2(기능 한 세트)** — **중요**: 지금 코드는 자리 하나(`source` 한 장)를 모든 칸에 쓴다. 분류별·자세별 여러 장을 쓰려면 **목록 구조와 화면 연결이 함께 필요하다(코드 미확정)**. 그림 한 장만 만들면 격자 전체가 같은 그림이 된다.

### 5. `expressionGuideArtwork` — 표현 가이드 카드 그림
- 화면: 홈 › 표현 가이드 카드 윗부분 (`App.tsx:604`), 2열 카드
- 역할: "무엇을 그릴까?" — 표현 이름(안녕·고마워…)을 그림으로 먼저 보여 준다
- 표시 크기(반응형): 틀 = floor((화면폭 − 32 − 12) / 2) − 20 → 360dp **138dp** · 384dp **150** · 412dp **164**, 그림은 틀의 **80%**(110 · 120 · 131dp)
- 권장 원본: 360px(@3x) · 240 · 120 / 마스터 1024 **× 카드 수**
- 비율·형식: **1:1 · PNG · 투명 배경** · contain(잘리지 않음)
- 안전 영역: 가운데 84%, 바닥선 90%. 표정·몸짓만으로 뜻이 읽혀야 한다(**글자 금지**)
- 앱이 따로 그리는 글자: 표현 이름(예: '안녕'), 몸짓 힌트(예: '손 크게 흔들기')
- 현재: **없음**(`EXPRESSION_GUIDE.ready = false`) · 우선순위 **P2(기능 한 세트)** — **중요**: 카드가 20장인데 코드는 자리 한 장을 모든 카드에 쓴다. 카드마다 다른 그림을 넣으려면 **카드별 그림 연결이 필요하다(코드 미확정)**.

### 6. `motionExampleArtwork` — 움직임 효과 견본 캐릭터
- 화면: 그리기 › 움직이기 › 효과 견본 (`motion-panel.tsx:149`). **그 칸에 사용자 그림이 있으면 사용자 그림이 먼저다** — 빈 칸에서만 이 그림이 움직인다.
- 표시 크기: 견본 칸 48dp 안에 **41×41dp**(86%) · 권장 원본 123(@3x) · 82 · 41 / 마스터 512
- 비율·형식: **1:1 · PNG · 투명 배경** · contain
- 안전 영역: 가운데 86% — 통통(위로 16%) · 흔들기(±9° 회전) · 두근거리기(1.14배)에도 칸 안에 남아야 한다
- 앱이 따로 그리는 글자: 효과 이름(통통 · 흔들기 · 두근거리기)
- 현재: **있음(임시)** `assets/art/mascot-paper.png` · 우선순위 **P3** — 임시 그림으로 기능이 성립한다. 공식 캐릭터가 정해지면 같이 바꾼다.

### 7. `exportSuccessArtwork` — 모두 완성했을 때 축하 그림
- 화면: 내보내기 › 요약 표면 오른쪽 (`App.tsx:959`), **완성 칸 수 = 세트 칸 수** 일 때만
- 표시 크기: **84×84dp** · 권장 원본 252(@3x) · 168 · 84 / 마스터 1024
- 비율·형식: **1:1 · PNG · 투명 배경** · contain · 안전 영역 가운데 84%
- 앱이 따로 그리는 글자: '세트를 모두 완성했어요 · 멈춰있는(움직이는) 이모티콘', '24 / 24 완성', 진행 막대
- 현재: **없음**(완성 전에는 퍼센트 원이 대신 선다) · 우선순위 **P2**

### 8. `proFeatureArtwork` (+ `sourceAfter`) — PRO 전·후 비교 두 장
- 화면: PRO 화면 위쪽 비교 표면 (`App.tsx:1215·1217`)
- 역할: '전체가 움직인다' vs '눈·팔·몸만 움직인다' 를 그림 두 장으로 보여 준다
- 표시 크기: **86×86dp 두 장**(16:9 표면 안, 가운데 화살표·아래 라벨은 앱이 그림) · 권장 원본 258(@3x) · 172 · 86 **× 2** / 마스터 1024 × 2
- 비율·형식: **1:1 · PNG · 투명 배경** · contain(잘리지 않음)
- 안전 영역: 가운데 84%, **두 장이 같은 캐릭터 · 같은 크기 · 같은 바닥선**이어야 비교가 읽힌다
- 앱이 따로 그리는 글자: '전체 움직임' / '눈·팔·몸만' 라벨과 화살표
- 현재: **있음(임시)** `assets/art/mascot-paper.png`(전) / `assets/art/mascot-ink.png`(후) · 우선순위 **P1** — 결제 화면의 설득 근거라 임시 그림으로 두기 가장 아쉬운 자리다.

## 지금 들어 있는 그림 두 장 (임시)
| 파일 | 실제 크기 | 용량 | 쓰이는 곳 |
|---|---|---|---|
| `assets/art/mascot-paper.png` | **276×306** (1:1 아님) | 126,026 바이트 | `motionExampleArtwork`(41dp 칸) · `proFeatureArtwork` 전(86dp) |
| `assets/art/mascot-ink.png` | **103×132** (1:1 아님) | 14,060 바이트 | `proFeatureArtwork` 후(86dp) |

- 둘 다 **1:1 자리에 들어간 세로형 그림**이라 contain 으로 줄어들어 칸을 다 채우지 못한다(예: 86×86 자리에 78×86 으로 앉는다). 자리 규격대로 만들면 이 여백이 사라진다.
- **이 두 장은 앱 기본 그림일 뿐 공식 캐릭터로 확정된 것이 아니다.** 캐릭터 확정은 별도 결정이다.

## 8장을 다 만들 필요는 없다 — 자리별 판단
- **지금 만들 값이 큰 곳(P1)**: `homeHeroArtwork`, `proFeatureArtwork`(2장) — 첫인상과 결제 설득에 바로 쓰인다.
- **기능을 켤 때 한 세트로(P2)**: `referencePoseThumbnail`, `expressionGuideArtwork` — 각각 여러 장 + 코드 연결이 함께 필요하다. **한 장만 만들면 모든 칸/카드가 같은 그림이 된다.**
- **없어도 되는 곳(P3)**: `homeEmptyArtwork`(설치 직후 1회 · 글자 두 줄로 충분), `noticeArtwork`(공지 기능이 꺼져 있어 화면에 없음), `motionExampleArtwork`(임시 그림으로 성립).
- **중간(P2)**: `exportSuccessArtwork` — 완성 순간에만 보이지만 그때 인상이 남는다.
- 출시를 막는 **P0 는 이 8자리가 아니라** 브랜드·스토어 에셋(앱 아이콘 · 적응형 아이콘 · 스플래시 · 스토어 아이콘 · 피처 그래픽 · 스크린샷)이다 — `docs/ASSET_INVENTORY.md` 앞쪽 ASSET REPLACEMENT CONTRACT 와 `npm run assets:check`.

## 미확정으로 남는 값
- 카드별·자세별 그림을 쓰는 구조(`expressionGuideArtwork` · `referencePoseThumbnail`): 코드에 아직 없다.
- 실제 기기 화면에서의 크기감·대비·잘림: **미확인**(`docs/MANUAL_QA.md` 45.13 검수표에서 확인한다).
- 공식 캐릭터 디자인(생김새·색·선 두께): 정해진 바 없음.
