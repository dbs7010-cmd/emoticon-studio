## 1. 지우개 → 펜 전환 — 재현하고 고쳤다

### 원인: 같은 명령이 **두 곳에서 조용히 버려졌다**

| 곳 | 무엇 |
|---|---|
| 엔진 `command()` | `if(saving && !['saved','saveFailed','analyze','save'].includes(m.type)) return;` — 자동저장 중 `tool` 을 통째로 버림 |
| `painter.tsx` `send()` | 같은 구간에 `held` 큐로 미룸 |

앱은 획을 끝낼 때마다 조용히 자동저장한다. 그 사이 펜을 고르면 UI 는 펜으로 바뀌지만
엔진은 지우개 그대로라 **다음 획이 지워졌다.**

### 수정

* 그림(레이어 비트맵)을 건드리지 않는 명령(`tool`·`brush`·`brushSettings`·`color`·`width`)은
  저장 중에도 **바로** 받고 바로 보낸다. 저장은 시작할 때 선택을 이미 확정하므로
  저장 중 `tool` 이 그림을 바꿀 일이 없다.
* 한 획은 **시작할 때의 도구**로 끝까지 그린다(`strokeTool`). 획 도중 도구가 바뀌어도 반 토막 나지 않는다.
* **setTimeout 으로 가리지 않았다.** 명령 순서를 바꾼 것이 아니라 버리지 않게 한 것이다.

### 검증 — UI 선택값이 아니라 **픽셀**

`scripts/_eraser-probe.cjs` · 같은 줄의 잉크 픽셀 수(정상 3288px)

| 시험 | 수정 전 | 수정 후 |

| 자동저장 없이 전환 | 3288 | 3288 |
| **자동저장 중 전환** | **0 (지워짐)** | **3288** |
| 자동저장 끝난 뒤 전환 | 3288 | 3288 |
| **획 도중 도구 변경** | **1182 (반 토막)** | **3288** |
| 지우개는 활성 레이어만 | 3288 | 3288 |

자료: `eraser-before/result.json` · `eraser-after/result.json`

### 충돌한 과거 결정

`product-ux-test.cjs` 가 **'저장 중에 누른 도구는 모아 둔다'** 를 못 박고 있었다.
그 규칙이 바로 이 결함의 원인이므로 이번 지시(§3)에 따라 뒤집고, 왜 뒤집었는지 시험 안에 적었다.

## 2. 검수용 PRO 접근

기능 자체는 있었다. 문제는 **`EMOTICON_INTERNAL_REVIEW=1` 로 빌드한 APK 에서만 보인다**는 것이었다 —
평범한 `npx expo start` 개발 실행에서는 스위치가 그려지지 않아 결제 안내에 막혔다.

| 항목 | 상태 |
|---|---|
| 볼 수 있는 환경 | `reviewCapable()` = 내부 검수 빌드 **또는 개발 실행(`__DEV__`)** |
| 설정 안 스위치 | 있음 · 켜고 끌 수 있음 · 재실행 후 유지(저장소에 남는다) |
| 잠긴 기능에서 바로 | PRO 안내에 '결제 없이 검수용 PRO 켜기' |
| 무엇에 반영되나 | `pro = isPro(entitlement) || reviewUnlocked(store)` — 브러시·부분 움직임·일괄 적용 모두 같은 값을 본다 |
| 화면이 스스로 말함 | '내부 검수용 빌드' / '개발 실행' 중 어느 쪽인지 표시 |
| 출시 구성 | 둘 다 거짓 → 스위치가 그려지지 않고, 저장된 값도 권한으로 인정되지 않는다 |
| 실제 구매 권한 | 손대지 않았다. `entitlement` 와 따로 둔다 |

**켜는 법**: 설정 → '검수용 PRO' 스위치. 또는 잠긴 기능을 눌렀을 때 뜨는 안내에서 바로.

## 5. 브러시 전체 목록

작은 카드 격자(한 칸에 같은 V자 견본)를 **한 줄에 한 브러시**로 바꿨다.

| 항목 | 상태 |
|---|---|
| 행 높이 | 68dp (목표 64~76dp 안) |
| 이름 칸 / 견본 칸 | 분리(이름 104dp 고정, 견본이 남은 가로폭 전부) |
| PRO | 이름 옆 작은 배지. 잠긴 것도 이름·견본 선명 |
| 선택 | 행 전체 |
| 압정 | **견본 위에서 걷어냈다.** '즐겨찾기 편집' 모드로 들어가 줄을 고르면 1·2·3번 칸을 묻는다 — 지금 그 칸에 무엇이 있는지 함께 보여 준다 |
| 머리줄 | 제목 · 즐겨찾기 편집 · 닫기 (닫기 하나) |
| 목록 열리면 | 아래 즐겨찾기 줄이 접힌다. 닫으면 돌아온다 |

패널 높이는 **즐겨찾기 줄이 있을 때의 캔버스**를 기준으로 잰다 — 줄이 접혀 캔버스가 커졌다고
패널이 따라 커지면, 사용자가 보던 캔버스로는 절반을 넘게 가리게 된다.

320dp 화면에서 '캔버스 절반' 이 패널 최소 높이(160dp)보다 작아 규칙을 넘던 것도 함께 고쳤다 —
하한을 캔버스에 맞춰 함께 내린다. 넘지 않는 것이 먼저다.

## 6. 전체 움직임 — 셋에서 여섯으로

**이름만 다른 같은 움직임을 새 종류로 세지 않았다.** 기존 세 id 는 그대로 두고 셋을 더했다.

| 이름 | 엔진 id | 무엇을 하나 | 새것/고침 |
|---|---|---|---|
| 둥실 | `float` | 부드러운 위아래 이동만 | 새것 |
| 통통 | `bounce` | 뛰고 **착지에서 눌림/늘어남** | 고침(눌림을 착지에 맞춤) |
| 두근거리기 | `pulse` | 크기만 | 그대로 |
| 까딱 | `tilt` | 작은 좌우 회전만 | 새것 |
| 흔들기 | `shake` | 짧고 빠른 좌우 이동 | 고침(회전을 뺐다 — 회전은 까딱의 몫) |
| 부르르 | `jitter` | 작은 범위의 빠른 떨림 | 새것 |

전체 움직임은 **전부 무료**다. 부분/순서의 PRO 정책은 그대로다.

### 검증 — 화면 재생이 아니라 **내보낸 GIF**

`scripts/_motion-probe.cjs` + `scripts/_gif.cjs`(GIF 해독기). 엔진이 구운 실제 출력 파일을 프레임으로 풀어
프레임마다 그림의 자리·크기·기울기를 읽었다.

| 효과 | 프레임 | 간격 | 가로 | 세로 | 폭 | 높이 | 기울기 |
|---|---|---|---|---|---|---|---|
| 둥실 | 10 | 80ms | 0.1 | **24.0** | 0.0 | 1.0 | 0.1 |
| 통통 | 10 | 80ms | 0.1 | **24.3** | **12.0** | **23.0** | 0.1 |
| 두근거리기 | 10 | 80ms | 0.2 | 1.6 | **16.0** | **27.0** | 0.2 |
| 까딱 | 10 | 80ms | 0.9 | 0.2 | 1.0 | 1.0 | **24.3** |
| 흔들기 | 10 | 80ms | **24.0** | 0.1 | 0.0 | 0.0 | 0.5 |
| 부르르 | 10 | 80ms | **8.3** | **7.3** | 1.0 | 1.0 | **5.6** |

**여섯이 서로 다르다.** 프레임 수 10 · 간격 80ms · 투명도 유지 — 출력 쪽도 같은 자리에서 확인했다.

> **검수 환경 문제와 제품 결함의 구분**: 처음에는 화면 재생(rAF)으로 재려 했는데 여섯 다 '움직이지 않음'
> 으로 나왔다. 원인은 **브라우저 창이 숨겨져 있으면 크롬이 rAF 를 멈추는 것**이었다 — 제품 결함이 아니다.
> 같은 이유로 이번 회차의 렌더 스크립트는 획 사이 쉼을 타이머 대신 메시지 한 바퀴로 센다.

## 7. 홈 가이드 표시용 이미지

카드 그림은 선만 있고 속이 비어 있어, 파스텔 카드 위에 올리면 배경색이 몸 안으로 비친다.
표시용 사본은 틀에서 흘려 넣어 **닿지 않은 곳을 몸 안**으로 보고 거기만 흰색을 깐다.

**'잘 자 · 이불'** 은 오른쪽에서 윤곽선 두 개가 만나지 않고 끊겨 있어, 흘린 물이 이불 속으로
그대로 들어갔다 — 그래서 이불만 투명하게 남았다.

### 수정

선을 잠깐 굵혀 틈을 잇고, 채운 뒤 굵힌 만큼 도로 물린다. **필요한 그림에만** 단계적으로 쓴다.
굵히기가 좁은 부위(팔과 얼굴이 만나는 자리)를 통째로 막으면 그 자리가 홈이 되므로,
**얻는 것이 잃는 것의 열 배보다 적으면 그 판을 버린다.**

| | 이전 | 지금 |
|---|---|---|
| 표시용 그림 | 63장 | **67장** |
| 이불 채움 | 11.6% | **32.3%** |
| 만들지 않음 | 18장 | **14장** |

바깥은 그대로 투명하다 — 그림 전체를 흰 사각형으로 덮지 않았다. 원본은 건드리지 않았다.
`blanket-before.png` · `blanket-after.png` (파스텔 3색 위) · `blanket-zoom.png`(4배, 끊긴 자리) ·
`display-gapfixed.png`(틈을 이은 것들)

### 남은 것 — 원본을 고쳐야 한다

**14장**은 윤곽선이 끊겨 채울 수 없다. 파일 이름과 필요한 작업을 `display/INDEX.json` 에 적었다:
`angry-angry-face` · `angry-annoyed-facepalm` · `angry-annoyed-sigh` · `angry-hmph-pout` ·
`angry-hmph-turn` · `daily-good-night-drowsy` · `sad-are-you-okay-chest` · `sad-are-you-okay-face` ·
`sad-are-you-okay-mouth` · `surprise-flustered-glance` · `surprise-gasp-face` · `surprise-no-way-face` ·
`surprise-what-question` · `surprise-what-side-eye`.

만든 67장 중 **25장에는 몇 px 짜리 작은 홈이 남는다**(가장 큰 것이 이불 19px = 그림의 0.1%).
몸 전체가 비치는 것보다 낫지만 원본을 고치면 없어진다 — 숨기지 않고 `INDEX.json` 에 적었다.
**자동 채우기를 돌린 것 자체를 완료 근거로 삼지 않았다.**

### 검수용 PRO 켜는 법

1. **내부 검수 APK**: 설정 → '검수용 PRO' 스위치. 또는 잠긴 기능을 눌렀을 때 뜨는 안내에서 '결제 없이 검수용 PRO 켜기'.
2. **개발 실행**: 같은 자리. 45.34 부터 개발 실행에서도 보인다.

### 개발 실행 명령

```
npx expo start --go
```

검수용 PRO 를 미리 켜 두고 싶으면 내부 검수 구성으로 띄운다:

```
EMOTICON_INTERNAL_REVIEW=1 npx expo start --go
```
