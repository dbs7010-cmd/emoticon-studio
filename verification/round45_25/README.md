# ROUND45.25 — 실기기 검수 5건 + 브러시 개선

시작 HEAD `99d1d9e`. 45.24 의 UI 마감 판정은 철회된 상태에서, 사용자가 실기기에서 확인한 5건과 브러시 6번을 고쳤다.
**APK 는 만들지 않았다** — 편집 화면 배치를 검토받기 전에는 다시 빌드하지 않는다는 지시에 따른다.

## 1. 홈/표현 가이드 캐릭터

원본은 선만 있고 속이 비어 있다. 직접 재 보니 **불투명한 픽셀이 4%** 이고 **선 사이의 80% 가 투명**이라, 파스텔 카드 위에 올리면 배경색이 몸 안으로 그대로 비쳤다(`scripts/_alpha.cjs`).

고친 법: 테두리에서 시작해 투명한 곳을 타고 들어가 '바깥'을 표시하고, **그러고도 닿지 않은 곳만** 흰색으로 깔아 원본을 그 위에 합성한다(`scripts/make-display-assets.cjs`).

- 바깥은 그대로 투명하다. 그림 전체를 흰 사각형으로 덮지 않았다.
- **원본은 건드리지 않았다.** 밑그림으로 캔버스에 깔리는 것은 여전히 원본이다(`artwork`). 보여 줄 때만 표시용(`display`)을 쓴다.
- 81장 중 **63장**을 만들었다. 채운 넓이 최소 11.6% · 중앙값 24.8% · 최대 39.1%.

### 만들지 못한 18장 — 표시용 에셋이 필요한 목록

선이 끊겨 흰색이 바깥으로 샐 수 있어 **억지로 칠하지 않고 남겼다**. 이 18장은 제대로 된 표시용 그림이 따로 필요하다.

```
angry-angry-face          angry-annoyed-ears        angry-annoyed-facepalm
angry-annoyed-head        angry-annoyed-sigh        angry-hmph-pout
angry-hmph-turn           daily-good-night-drowsy   sad-are-you-okay-chest
sad-are-you-okay-face     sad-are-you-okay-lean     sad-are-you-okay-mouth
surprise-flustered-glance surprise-flustered-sweat  surprise-gasp-face
surprise-no-way-face      surprise-what-question    surprise-what-side-eye
```
(기계가 읽을 목록: `assets/expression-guides/display/INDEX.json`)

이 가운데 **감정 대표 그림 5장**(괜찮아? · 흥 · 짜증나 · 당황 · 설마)이 들어 있다. 그 다섯은 감정 목록에서 여전히 바탕색이 몸으로 비친다.

또 하나의 한계: 그림의 일부가 **이미지 가장자리에 닿아 있으면** 그 부분은 닫힌 자리가 아니라 채워지지 않는다. '잘 자'의 이불이 그 예다(머리는 희게 찼고 이불은 그대로다).

## 2. 캔버스 도구 — 시안 대조

`docs/UI_SPEC_VS_BUILD.md` 에 13행 표로 적었다. 기준으로 삼은 것은 저장소에 있는 **승인 시안** 두 장(`docs/design/approved-*.png`)이다. 처음 전달된 `IMPLEMENTATION_SPEC.md` 원본은 저장소에 없어, 그림으로 확인할 수 있는 것만 적었다.

- **이번 지시로 시안과 달라진 것**: 참고 보기(떠 있는 창 → 캔버스 밖 자리), 굵기(가로 슬라이더 → 캔버스 밖 세로 조절대).
- **기준을 찾지 못해 바꾸지 않은 것**: 머리줄의 되돌리기·완료 자리, 브러시 카드 상시 노출, 도구 줄의 '색', 작업 도구 메뉴. 추측으로 전면 수정하지 않았다.

## 3. 밑그림 삽입

밑그림을 깔면 **그 위에 빈 그림 장을 하나 만들고 바로 고른다**(엔진의 `addLayer` → `selectDrawLayer`).

- 기존 장은 그대로 아래 남는다. 지우거나 덮어쓰는 명령은 보내지 않는다.
- 한 번의 삽입에 한 장만 생긴다.
- **실패하면 여기까지 오지 않아** 빈 장만 남는 일이 없다.
- 같은 밑그림을 다시 보이기만 할 때는 만들지 않는다.
- 네 장이 다 차면 그림을 건드리지 않고 왜 못 만드는지 말한다.

## 4. 참고 보기

캔버스 **밖** 전용 자리로 옮겼다(`GuideStrip`). 접기·펼치기·닫기가 있고, 옮기기·크기 손잡이는 사라졌다 — 자리가 정해져 있기 때문이다.

- 자리를 차지하면 아래 캔버스 영역이 줄고, 정사각 캔버스가 남은 자리에 다시 맞춰진다.
- 논리 해상도(360×360)와 저장 좌표는 바꾸지 않았다. 엔진은 제 DOM 상자 기준으로 터치를 옮기므로 확대·이동도 그대로 따라간다.
- 같은 말을 캔버스 위에 또 띄우던 한 줄 토스트는 물러났다.
- **'캔버스 자리 고정' 검사를 최신 요구에 맞게 고쳤다**: 그 규칙은 이제 **덮어 뜨는 판**(브러시·색·레이어·문구)에만 걸린다. 참고 자리는 일부러 캔버스를 줄인다.

## 5. PRO 검수

토글과 잠금은 **코드가 이미 맞았다**. 새 검사(`scripts/review-pro-test.cjs`)로 토글 → 홈 배지 · 부분 움직임 · 고급 브러시가 함께 열리고 함께 잠기는 것을 끝에서 끝까지 확인했다. 출시 구성에서는 토글이 아예 그려지지 않는 것도 함께 본다.

진짜 막힌 것은 **길**이었다: 검수 기기에서는 결제를 열 수 없는데 잠금 안내에는 결제 버튼뿐이라, 설정 깊은 곳의 토글을 찾아야 했다. 막힌 그 자리에 **'결제 없이 검수용 PRO 켜기'** 를 뒀다. 출시 구성에서는 그려지지 않는다.

## 6. 펜/브러시 도구

- 브러시를 고르면 그 도구가 켜지고 **선택판이 스스로 닫힌다**(고급 브러시도 같다).
- 기본 영역에는 펜·붓·연필만. 고급 브러시는 **작은 진입점 한 줄**이고 실제 고르기는 세부 설정 안에서 한다.
- **획 미리보기는 기존 엔진이 그렸다**(`scripts/_strokes.cjs`): `canvas-html.ts` 를 띄우고 같은 자리·같은 굵기(14px)로 같은 곡선을 포인터 사건으로 그어 받은 출력이다. 따로 그리지 않았다.
- **고르지 않은 항목을 흐리게 하지 않는다** — 흐리면 '못 쓰는 것'처럼 읽혀 셋을 견줄 수가 없다.
- 굵기는 캔버스 **밖** 오른쪽 세로 조절대. 끄는 동안 수치와 원형 미리보기가 뜬다(예전부터 있던 동작).
- 펜 계열과 지우개의 굵기는 예전처럼 따로 기억한다(엔진의 `penWidth` / `eraserWidth`).
- 색 패널과 브러시 선택판은 `panel` 하나로 갈려 동시에 열리지 않는다.
- 패널을 닫는 첫 캔버스 터치는 `패널 닫기 막` 이 받아 획을 만들지 않는다.

### 엔진을 재 보고 찾은 것 — **붓이 펜과 같은 획을 낸다**

획 견본을 엔진으로 만들면서 세 브러시의 실제 획을 쟀다(14px, 같은 곡선):

| 브러시 | 획 굵기(세 자리에서 잰 값) | 최대 불투명도 | 덮인 넓이 |
|---|---|---|---|
| 펜 | 19 / 18 / 27 px | 255 | 5.3% |
| 붓 | 19 / 18 / 27 px | 255 | 5.3% |
| 연필 | 27 / 25 / 37 px | 255 | 7.3% |

**펜과 붓은 완전히 같다.** 소스에는 붓을 `굵기 ×1.4 · 알파 0.85` 로 그리는 식이 있지만 확정된 획에는 적용되지 않는다. 연필만 눈에 띄게 다르다.

미리보기를 과장하지 말라는 지시에 따라 **그대로 두고 보고한다** — 셋 중 둘이 같아 보이는 것은 미리보기 탓이 아니라 엔진이 그렇게 긋기 때문이다. 엔진 수정은 이번 지시에 없어 손대지 않았다.

## 남은 문제

1. 표시용 그림 18장(감정 대표 5장 포함)은 만들지 못했다. 위 목록 참조.
2. 그림이 이미지 가장자리에 닿는 부분은 채워지지 않는다('잘 자'의 이불).
3. **붓이 펜과 같은 획을 낸다** — 엔진 쪽 문제이고 이번에 손대지 않았다.
4. 시안과 다른 네 가지(머리줄 자리 · 브러시 상시 노출 · 도구 줄의 색 · 작업 도구 메뉴)는 근거를 찾지 못해 그대로 뒀다.
5. APK 는 만들지 않았다. 편집 화면 배치를 검토받은 뒤에 한 번 만든다.
