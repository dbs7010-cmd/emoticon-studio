6. 비밀번호·키 파일·키 별칭 값을 저장소·문서·로그에 쓰지 않는다(`docs/RELEASE_SIGNING.md` §2).

8. Expo SDK 57 문서를 먼저 읽고 코드를 쓴다(`AGENTS.md`). 새 의존성은 넣지 않는다(필요하면 사유와 함께 보고).
9. 설정값은 지어내지 않는다. **개인정보처리방침 URL·문의 이메일은 아직 없다** — 빌드 설정으로 주입받고, 없으면 그 항목이 어떻게 보일지를 아래대로 구현한다.

## C2. 설정의 개인정보처리방침 · 문의 진입점 (K2)

**할 일:**
- 설정 창에 두 줄을 추가한다. 위치는 '버전' 근처다.
  - **개인정보처리방침:** 빌드 설정 `extra.privacyPolicyUrl`(https만)을 `Linking`으로 연다.
  - **문의하기:** 빌드 설정 `extra.supportEmail`로 `mailto:`를 연다.
    - 제목: `[임티제작소] 문의`
    - 본문: 앱 버전·기종 OS 버전만 넣는다. 그림·세트 이름·파일 같은 개인 작업 내용은 넣지 않는다.
    - 기존 '문의용 파일 보내기'(복구 화면)는 그대로 둔다.
- 값은 `app.config.js`가 환경변수에서 받는다.
  - `EMOTICON_PRIVACY_URL`, `EMOTICON_SUPPORT_EMAIL`
  - 형식이 틀리면 넣지 않는다(`receiptEndpoint`와 같은 방식).
- 값이 없을 때:
  - 내부 검수 빌드: 그 줄에 '준비 중'이라고 적고 누르지 못하게 한다.
  - 출시 구성: `release-check`가 **FAIL [OWNER]**로 막는다.
    - 새 항목: `privacy_url`, `support_email`
    - AAB 안의 `app.config`에서도 판독한다.
- 여는 데 실패하면(메일 앱 없음 등) 이메일 주소를 보여 주고 복사할 수 있게 한다.

**완료 조건:**
- 두 줄이 보인다.
- 값이 있으면 누를 때 `Linking.openURL`이 맞는 값으로 불린다.
- 값이 없으면 '준비 중'이고 누르지 못한다.
- `release-check` 새 항목의 FAIL/PASS 검사가 있다.

## C3. 홈 / 내보내기 '손볼 곳' 수 일치 (K11)

**지금 문제:**
- 같은 세트에서 홈은 '손볼 곳 없음', 내보내기는 '손볼 곳 2개'(남은 칸 · 같은 그림)로 보인다.
- 원인:
  - 홈(`App.tsx` '제안까지 남은 일')은 남은 칸을 따로 세고, 같은 그림 비교를 뺐다.
  - 내보내기(`setChecks`)는 남은 칸 + 같은 그림 + 겹친 문구 + 크기 + 배경 + 자동 검사를 센다.

**할 일:**
- 판정을 **한 함수**로 모은다. 예: `src/project.ts`의 `setIssues(project, options)`.
- 홈과 내보내기가 같은 함수를 쓴다.
- 규칙:
  - 두 화면의 '손볼 곳' 숫자는 **같은 세트에서 같아야 한다.**
  - 남은 칸을 손볼 곳에 넣을지는 한쪽으로 정한다. 권장: **남은 칸은 두 화면 모두 손볼 곳이 아니라 별도 진행 표시.** 내보내기의 '남은 칸' 항목은 진행 요약으로 옮긴다.
  - '같은 그림' 비교는 파일을 읽는다(`identicalFinals`).
    - 홈을 그릴 때마다 동기 파일 읽기를 하지 않는다.
    - 그림 경로 기준으로 기억(memo)해 한 번만 계산한다. 비동기로 계산하고, 계산 중에는 '확인 중'으로 표시한다.
    - 이것이 과하면, 저장할 때 그림 요약값(해시)을 기록하는 방식도 괜찮다. 단 기존 저장본은 없어도 읽혀야 한다.

**완료 조건:**
- 같은 저장소(같은 그림 · 겹친 문구 · 크기 어긋남 · 배경 · 자동 검사 FAIL 조합)로 홈과 내보내기를 렌더했을 때 숫자와 항목 이름이 같다(새 검사).
- 45.39 홈 검사(`visual-system`·`ui-structure`)가 계속 통과한다.

## C4. `SYSTEM_ALERT_WINDOW` (K9)

**할 일:**
1. 유입 원인을 찾는다. `android/app/build/outputs/logs/manifest-merger-release-report.txt` 또는 `processReleaseMainManifest`의 병합 보고서에서 이 권한이 어느 매니페스트에서 왔는지 확인한다(템플릿 `src/main` · `src/debug` · 라이브러리).

3. 불필요하면 **설정 플러그인**으로 병합 매니페스트에서 제거한다(`tools:node="remove"`). prebuild를 다시 해도 유지돼야 한다. `android/`를 손으로 고쳐 두지 않는다.
4. 개발 빌드(`expo-dev-client`)의 개발 메뉴가 이 권한을 필요로 하면 **release 변형에서만** 뺀다.

**완료 조건:**

- 보고에 유입 원인(파일·줄)을 적는다.
- `release-check`에 '쓰지 않는 권한 없음' 항목을 추가하면 좋다(선택).

## C7. 구매를 닫은 비공개 테스트 빌드 구성(무료 테스트용)

**지금 문제:**
- `release-check`는 영수증 서버 주소(`receipt_endpoint`)가 없으면 **CONFIG FAIL로 업로드를 막는다.**
- 그래서 결제 서버가 준비되기 전에는 무료 기능 비공개 테스트 AAB도 올릴 수 없다.
- 서버 주소 없이 올리면 PRO 화면이 '가격을 불러오지 못했어요'라는 **오류처럼** 보인다.

**할 일:**
- 빌드 설정 `EMOTICON_PURCHASES=closed`를 추가한다. 이 값이 있으면 `extra.purchases = 'closed'`이다.
- 이 구성에서 PRO 화면은:
  - 기능 소개(C1)는 그대로 보인다.
  - 가격 조회·구매·복원 버튼 대신 **'이번 테스트 버전에서는 PRO 구매가 아직 열리지 않았어요. 무료 기능을 모두 쓸 수 있어요.'**를 보인다.
  - 스토어 호출을 하지 않는다.
- 무료 사용자가 PRO 효과 미리보기를 누르는 흐름(45.39)은 그대로 둔다. 'PRO로 쓰기'를 누르면 위 안내로 간다.
- **검수용 우회를 이 구성에 섞지 않는다**(`internalReview`는 계속 false. 무료 테스터는 PRO를 쓸 수 없다).
- `release-check`:
  - `--track closed-free`(또는 `extra.purchases==='closed'` 판독)일 때만 `receipt_endpoint` 누락을 **WARN**으로 내린다.
  - 다른 항목(서명·internal_review_off·BILLING 권한 등)은 그대로 FAIL이다.
  - 정식 출시 구성(`purchases` 없음)에서는 지금처럼 FAIL이다.
- AAB 안의 `app.config`에서 `purchases`를 판독하는 항목을 추가한다.

**완료 조건:**
- 구성별 PRO 화면 검사:
  - closed: 스토어 호출 0회, 안내 문구가 보인다.
  - 정식: 지금처럼 동작한다.
- `release-check` 판정 검사: closed-free에서 서버 주소 없음은 WARN, 서명 없음은 FAIL.
- `iap-test`·`pro-test`·`review-pro-test`가 계속 통과한다.
