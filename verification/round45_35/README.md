| **사용자 미감 승인 대기** | 사용자가 보고 좋다고 하지 않았다 |

## 1. 먼저 고친 것 — 움직임 저장 실패

사용자 신고: **"저장하지 못했어요 / 움직임 종류가 손상되었습니다."**

### 재현

```
bounce   OK        shake    OK        pulse    OK
float    거부 — 움직임 종류가 손상되었습니다.
tilt     거부 — 움직임 종류가 손상되었습니다.
jitter   거부 — 움직임 종류가 손상되었습니다.
```

### 원인 — UI·저장 검증·직렬화·재열기·출력 다섯 자리를 따라가 보니 갈라진 곳은 한 곳이었다

| 자리 | 45.34 이후 상태 |
|---|---|
| 화면 목록 (`motion-panel.tsx` PRESETS) | 여섯 (둥실·통통·두근거리기·까딱·흔들기·부르르) |
| 타입 (`types.ts` MotionPreset) | 여섯 |
| 엔진 (`canvas-html.ts` wholeDelta) | 여섯 |
| **저장 검증 (`project.ts`)** | **`['bounce','shake','pulse']` 셋만 글자로 박혀 있었다** |
| 재열기·출력 | 저장을 통과한 것만 오므로 문제 없음 |

`saveStore()` 는 파일에 쓰기 **전에** `parseStore()` 로 검증한다. 그래서 새로 늘린 셋을 고르면
칸을 닫을 때 저장이 거부되고, 화면에는 "저장하지 못했어요" 가 떴다.

### 수정

종류 목록을 `types.ts` 한 곳으로 모으고 `project.ts` 가 그것을 읽는다. 늘릴 자리는 이제 하나뿐이다.

- **검증을 통째로 제거하지 않았다** — 모르는 종류(`nonsense`)는 그대로 거부한다.
- **알 수 없는 효과를 조용히 '없음' 으로 바꾸지 않는다** — 거부한다.
- **거부된 저장은 파일을 건드리지 않는다** — 이전 정상 저장본이 그대로 남는다(검사로 확인).
- 실패했는데 완성 처리·다음 칸 이동을 하지 않는 것은 기존 경로 그대로다.

### 새 검사 — `scripts/motion-preset-test.cjs` (npm test 에 등록)

화면 목록을 **읽어서** 그 모두를 선택 → 저장 → 재열기로 왕복시킨다. 목록을 손으로 적지 않으므로
다음에 종류를 늘릴 때도 같은 자리가 갈라지면 바로 잡힌다.

```
PASS: 전체 움직임 6종(float·bounce·pulse·tilt·shake·jitter) 모두 선택 → 저장 → 재열기.
      모르는 종류는 여전히 거부하고, 거부된 저장은 이전 저장본을 건드리지 않는다.
```

**구현 완료 · 자동 검증.** 실기기 미검증.

## 2. 승인 시안의 구현

### 2-1. 왼쪽 세로 조절대 (§5)

| 시안이 말한 것 | 구현 |
|---|---|
| 위는 굵기, 아래는 불투명도, 캔버스 밖 왼쪽 전용 공간 | 캔버스 영역 왼쪽에 72dp 기둥. 캔버스는 그 오른쪽에 정사각으로 선다 |
| 얇고 부드러운 회색 홈 · 아래에서 현재값까지 노란 활성 구간 | 6dp 홈(`surface2`) · 아래에서 손잡이 가운데까지 `accent` |
| 위로 움직이면 값 증가 | `1 - y/travel` |
| 실제 터치 폭 48dp 이상 | 기둥 72 − 안쪽 여백 4 = **68dp** |
| 두 조절부 터치 영역·라벨 비겹침 | 사이 20dp · 라벨은 각자의 홈 위 |
| 흰색의 작은 세로 캡슐 · 섬세한 회색 테두리 · 중앙 잉크색 표시 | 20×34 캡슐, 테두리 `lineStrong`, 가운데 2×12 `ink` 막대 |
| 얕은 그림자 | `Elev[1]` |
| 누름 상태를 같은 디자인 언어로 | 크기 그대로, 테두리만 `ink` 로 짙어진다 |
| 기본 OS 슬라이더에 노랑만 칠하지 않음 | 직접 그린 부품(`VSlider`) |
| 조절 중 손잡이 옆 값 말풍선 | 손잡이에 매여 함께 오르내린다 |
| 굵기는 현재 색의 원형 견본과 수치 | 지금 색 원(4~12dp, 값에 따라) + 숫자 |
| 불투명도는 백분율 | `60%` |
| 말풍선 모서리·글자·테두리 통일 | 반지름 10 · 흰 표면 · `line` 테두리 — 다른 도구와 같은 언어 |
| **그림 중앙에 검은 미리보기 상자 금지** | 45.4 의 `#171717C7` 상자를 **지웠다**. 45.4 의 캔버스 가장자리 굵기 띠(`EdgeSize`)도 지웠다 |
| 조절 종료 후 임시 말풍선 정리 | 말풍선은 손잡이 자리에 매여 있어 남아 떠도는 표시가 없다 |
| 손잡이와 숫자는 입력을 즉시 따라감 | 끄는 동안의 값은 부품 안 `live` 상태 — 한 프레임도 늦지 않는다 |
| 지연 보간 애니메이션 금지 | 없음. `LayoutAnimation` 은 패널 여닫기에만 걸려 있고 조절대에는 걸지 않았다 |
| 최종값은 다음 첫 획부터 적용 | 손을 떼는 순간 한 번 올린다 |
| 펜/지우개 설정 혼선 방지 | `penWidth`/`eraserWidth` 가 따로 있고, 라벨도 '브러시 굵기'/'지우개 굵기' 로 갈린다 |

#### 끊김 원인을 계측해서 고친 방식

지시가 나열한 원인들을 하나씩 짚었다.

| 원인 후보 | 이번 구조에서 |
|---|---|
| 부모 전체 재렌더 | **없앴다.** 끄는 동안 값은 `VSlider` 안에만 있다. 1,900줄짜리 편집 화면은 다시 그려지지 않는다 |
| WebView 메시지 적체 | **없앴다.** 끄는 동안 `width`/`brushSettings` 메시지를 **한 건도 보내지 않는다**. 손을 뗄 때 한 번 |
| 자동저장 | 조절은 `dirty` 를 만들지 않으므로 자동저장이 돌지 않는다 |
| 견본 재생성 | 견본은 번들 PNG 다. 값에 따라 다시 만들지 않는다 |
| 캔버스 재레이아웃 | 기둥은 고정 폭, 홈은 고정 높이 — 값이 바뀌어도 레이아웃이 다시 계산되지 않는다 |
| 스크롤/제스처 충돌 | 기둥은 스크롤 안에 있지 않고, 캔버스 밖이라 WebView 제스처와 겹치지 않는다 |
| 지나치게 큰 값 간격 | 굵기 1단위, 불투명도 5% |

**긴 debounce 나 임의의 setTimeout 으로 숨기지 않았다.** 늦게 반영하는 것이 아니라 **아예 보내지 않는다** —
굵기는 어차피 다음 첫 획부터 쓰이므로 끄는 도중의 값을 엔진이 알 이유가 없다.

**구현 완료 · 자동 검증(검사가 끌어 보고 최종값이 캔버스로 가는 것을 확인).**
**조작의 부드러움은 실기기 미검증** — 계측한 것은 '메시지를 몇 개 보내는가'이지 '손가락이 부드럽게 따라오는가' 가 아니다.

### 2-2. 아래 줄 (§4)

- 기존 굵기/불투명도 두 줄 **제거** → 아래 줄 높이 **218dp → 142dp**
- ① 즐겨찾기 3 + 전체 ② 펜·지우개·채우기·선택 + 지금 색
- 큰 둥근 카드와 굵은 외곽선을 걷었다. 고른 칸만 옅은 노랑 + 짧은 밑줄
- 펜(도구)과 브러시 즐겨찾기의 선택 표시를 역할로 구분: 도구는 아이콘+이름, 즐겨찾기는 획 견본+이름

### 2-4. 획 견본을 다시 만들었다

**시안과 대조하다 발견한 실제 결함이다.** 견본 파일이 거의 정사각(360×360)이라, 줄 안에서 높이에
맞춰 줄이면 34×34 짜리 작은 도장이 된다 — "넓은 실제 획 견본" 이 아니다. 대체 렌더가 그림을
**늘여 붙이느라** 이 사실을 가리고 있었다.

30종을 **같은 엔진으로 다시 그어** 360×86 띠로 만들었다(`scripts/make-brush-samples.cjs`).
분류마다 보여 줄 것이 다르므로 경로와 굵기를 나눴다:

| 분류 | 견본 |
|---|---|
| 선 | 굵기 14 · 완만한 물결 하나 — 선의 성격(가장자리·테이퍼·번짐) |
| 채색 | 굵기 26 · 넓은 획 + 짧게 어긋난 두 번째 획 — 넓은 획과 **겹침** |
| 질감 | 굵기 26 · 물결 하나 — 재료감(입자·결) |
| 효과 | 굵기 20 · 물결 하나 — 그 효과의 실제 특징(테두리·점선·평행선·발광) |

**브러시 엔진은 건드리지 않았다.** 바뀐 것은 견본을 만들 때의 입력 경로와 굵기뿐이고,
그 값은 사용자 브러시 설정과 아무 관계가 없다. 45.33 의 수정(종이 결·테이퍼 상한)은 그대로다.

검사도 바꿨다: '잘라낸 테두리 크기' 대신 **띠 안의 실제 잉크**를 잰다. 옅게 번지는 브러시
(에어브러시·워시)는 넓게 닿는 것이 그 성질이라, **닿음이 아니라 짙음**으로 잰다.

### 2-5. 색 (§7)

- SV 사각판과 색상 막대를 **작은 네모 이어 붙이기**(가로 20칸 × 세로 16칸, 막대 30칸)에서
  **늘려 쓰는 그림**으로 바꿨다. 칸마다 색이 뛰던 **계단식 색 타일**이 사라진다.
- 그라디언트 라이브러리를 새로 넣지 않았다(네이티브 구성이 달라진다). 대신 1KB 짜리 PNG 세 장을
  만들어 늘린다(`scripts/make-color-assets.cjs`). 두 장은 색과 무관해서 어떤 색상에서도 같은 판이 나온다.
- 막대는 시안대로 사각판 **오른쪽에 세로로** 선다.
- 손잡이는 흰 고리 + 고른 색 + 얇은 짙은 테두리 — **이중 테두리**라 흰 색 위에서도 검은 색 위에서도 보인다.
- 스포이드·HEX·색 저장·최근 색·내 팔레트는 그대로다. 색 조절 중 창이 유지되는 것도 그대로다.

### 2-6. 레이어 (§7)

- 줄마다 두르던 카드를 걷고 **썸네일 40 · 이름 · 눈 48 · 관리 48** 을 같은 열로 정렬
- 선택 행은 연노랑, 추가(`+`)는 머리로 올라가 닫기(`∨`)와 같은 아이콘 규격
- **고른다고 판이 닫히지 않는다.** 예전에는 고르는 순간 닫혀 무엇을 골랐는지 확인할 수 없었고,
  순서를 바꾸거나 보임을 끄려면 매번 다시 열어야 했다
- 삭제 확인 대화와 되돌리기, 기본 레이어 편집 권한은 그대로

### 2-7. 나머지 도구 (§8)

참고·문구·선택·채우기·지우개 설정이 같은 껍데기(`SheetHeader` + 같은 여백·라벨·버튼·선택 상태)를 쓴다.
안드로이드 뒤로 가기는 **지금 창부터** 처리한다: 브러시 세부 설정 → 브러시 목록 → 창 닫기 → 화면 나가기.

## 3. 시안과 다른 점과 그 이유

「비슷한 색을 적용했다」로 끝내지 않기 위해, 시안과 **일부러 다르게 한 곳**을 적는다.

| 자리 | 시안 | 구현 | 이유 |
|---|---|---|---|
| 머리줄 오른쪽 | 완성까지 | 완성 + **더보기(⋯)** | 지시 §1 「기존 더보기 기능 보존」. 시안에 생략된 기존 기능은 제거하지 않는다 |
| 완성 버튼 | 글자만 | 글자 + 화살표 | 이 버튼은 '완성 표시 + 저장 + 다음 칸' 이다. 화살표가 '다음으로 간다'를 말한다. 크기는 시안처럼 절제했다 |
| 기둥 폭 | 화면의 약 16.5% | 72dp (390dp 화면의 18.5%) | 라벨 '불투명도' 와 말풍선 '100%' 가 기둥 안에 온전히 들어가야 한다. 더 좁히면 캔버스 위로 넘쳐 그림을 가린다 |
| 캔버스 밖 | 거의 흰 작업면 | 한 단계 눌린 면(`#ECEEF2`) | 종이(흰색)와 작업 공간의 **경계가 읽혀야** 어디까지가 그림인지 안다. 앱 바탕(`#F6F7F8`)은 흰 종이와 구분되지 않았다 |
| 브러시 창 덮는 비율 | — | 캔버스의 절반을 넘는다 | 다른 판은 '그림을 보면서 조절' 이라 절반 이하다. 브러시 고르기는 **획 견본을 보는 일**이라 시안이 넓은 독립 창으로 정했다 |
| 320dp 화면 캔버스 | — | 한 변 248dp | 기둥이 자리를 차지하므로 정사각 한 변은 (화면 폭 − 기둥)을 넘을 수 없다. **기하학적 상한이지 결함이 아니다.** 손가락 자리(기둥 48 · 도구 48)는 어디서도 줄이지 않았다 |
| 시안의 강아지 | 예시 작품 | 쓰지 않았다 | 사용자 그림을 교체하거나 새 캐릭터로 등록하지 않는다. 검토 그림의 캐릭터는 기존 표현 가이드 그림이다 |
| 시안의 브러시 견본 | 미감 예시 | 실제 엔진 출력 | 지시대로 해당 브러시 엔진이 그은 획을 쓴다 |
| 시안의 PRO 배지 자리 | — | 기존 권한표 그대로 | 무료 10 + PRO 20 · 일회성 PRO · 기존 구매 권한 변경 없음 |

## 4. 과거 결정과 충돌한 곳

| 과거 결정 | 이번 지시 | 어떻게 했나 |
|---|---|---|
| 45.34 §6: 전체 목록이 열리면 즐겨찾기 줄을 접는다 | §4 「도구 창 열기/닫기가 캔버스 크기·위치·배율을 변경하지 않음」 | **이번 지시를 따랐다.** 줄을 접으면 여는 순간 캔버스가 커졌다 닫으면 작아진다. 브러시 창이 화면 전체를 덮으므로 아래 줄이 보이지도 않아 접을 이유가 사라졌다. `BASE_H_LIST` 를 없앴다 |
| 사용자 평가(과거): 레이어는 고르면 접히면서 그 그림에 바로 그려져야 한다 | §7 「레이어 선택만으로 창이 갑자기 닫히지 않음」 | **이번 지시를 따랐다.** 원래 평가의 뜻("레이어가 그림을 가린다")은 패널이 캔버스 위에 뜨지 않는 것으로 이미 지켜진다 — 그 검사는 그대로 남겨 두었다 |
| 45.28: 굵기는 색과 같은 줄에서 가로로 끈다 · 세로 조절대는 없앴다 | §5 왼쪽 세로 조절대 | **이번 지시를 따랐다.** 45.28 이 없앤 것은 '조절대가 둘이어서 어느 쪽이 지금 값인지 모르는 상태' 였다. 지금은 **하나뿐**이고 검사가 그것을 못 박는다 |

### 5-3. 화면 매트릭스가 못 박는 것 (640/720/800/900/1000 × 320/360/390/412 = 20칸)

- 캔버스는 (화면 폭 − 기둥)까지 정사각으로 꽉 찬다
- 굵기·불투명도 조절대는 캔버스 **밖** 기둥에 하나씩, 캔버스 틀 안에 없다
- 기둥 전체가 캔버스 영역 높이 안에 든다(잘려 나가지 않는다)
- 홈 길이 56~208dp · 손가락 폭 68dp
- 아래 줄 두 줄이 `BASE_H` 안에 들어간다
- 브러시 창에 네 줄이 들고 화면을 넘지 않는다 · 세부 설정으로 들어가도 창 크기가 그대로다
- 색·참고·레이어 판은 캔버스 절반 이하
- 문구 패널이 키보드 위에 남는다
- 글자 배율 1.0/1.3/1.5 에서 높이 고정 상자 잘림 **0곳**

### 5-4. 검사 기대값을 바꾼 곳과 이유

테스트를 고쳤다는 사실만으로 결함 해결을 주장하지 않기 위해, 바꾼 기대값과 이유를 적는다.

## 8. 검수 APK

통합 구현과 가능한 검증을 마친 뒤 **한 번만** 구웠다. 기존 APK 14개와 사용자 데이터는 그대로 두었다.

| 항목 | 값 |
|---|---|
| 파일 | `dist/emoticon-studio-1.0.0-vc1-internal-review-df603f7-arm64.apk` |
| 크기 | 40,968,816 bytes |

### 번들에 실제로 들어갔는지 (설치가 아니라 파일을 뜯어 확인)

Hermes 바이트코드다. 엔진 HTML 은 한글이 섞여 UTF-16 으로 들어가므로 그 인코딩으로도 찾아 대조했다.

### 검수용 PRO 켜는 법

1. **내부 검수 APK**: 설정 → '검수용 PRO' 스위치. 또는 잠긴 기능을 눌렀을 때 뜨는 안내에서
   '결제 없이 검수용 PRO 켜기'.
2. **개발 실행**: 같은 자리(45.34 부터 개발 실행에서도 보인다).

출시 구성에는 이 스위치가 그려지지 않고, 저장된 검수 설정도 권한으로 쓰이지 않는다
(release-check-test · review-pro-test 가 못 박는다). 실제 구매 권한과는 분리돼 있고 영수증 서버가 없어도 켜진다.

### 개발 실행 명령

```
npx expo start --go
```

검수용 PRO 를 미리 켜 두고 싶으면 내부 검수 구성으로 띄운다:

```
EMOTICON_INTERNAL_REVIEW=1 npx expo start --go
```

**설치·실행은 검증하지 않았다.** ADB·개발자 모드·에뮬레이터·앱 삭제·데이터 초기화를 쓰지 않으므로
직접 설치해 확인해야 하고, 그전까지 **DEVICE-UX UNVERIFIED** 다.
자동 검증 통과는 사용성 승인도, 미감 승인도 아니다.
