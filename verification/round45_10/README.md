## 정정 (45.11차, 2026-09-21) — 위 B 절의 설명 두 가지를 바로잡는다
위 본문은 당시 기록 그대로 둔다. 다시 재 보니 아래가 맞다(근거: `verification/round45_11/README.md` B·C 절, `preview-vs-export.json`, `export-boxes.txt`).

1. **"또박만 0.7% 차(PNG 인코딩 경계값)" 는 틀렸다.** PNG 는 무손실이다 — 같은 캔버스의 픽셀과 그 캔버스가 만든 PNG 를 직접 비교하면 달라진 픽셀 0 이다.
   실제 원인은 **화면 캔버스와 내보내는 캔버스가 같은 글꼴을 다르게 재고 다르게 그리는 것**이다(측정: `700 40px serif` 폭 273.0 vs 268.2, 그린 폭 269px vs 263px). 특정 문구 하나의 성질이 아니라 판마다 옮겨 다닌다.
   또 45.10 의 비교 방법(내보낸 PNG 를 브라우저에서 다시 그려 재기)은 ±1 의 잡음을 스스로 더한다 — 그 잡음까지 '인코딩 차이' 로 읽었다.
2. **"칸 폭 안에 들어온다(최대 309 < 328) → 잘림 없음" 은 근거가 부족했다.** 글자 획만 잰 값이었다. 흰 테두리까지 포함한 실제 자리를 재면 긴 문구(또박)는 **332px · 좌우 여백 14px** 로 16px 여백 규칙을 넘고 있었다.
   45.11 에서 칸 맞춤이 테두리까지 세도록 고쳤다(316px · 여백 22px). 또 **도톰은 가장 작은 크기에서 글자 속이 막힌다**(45.11 E-1, P2) — 45.10 의 '속이 막히지 않는다' 는 큰 크기에만 맞는 말이었다.
