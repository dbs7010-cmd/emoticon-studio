# ROUND45.24 — UI 마감

시작 HEAD `ed125a8`. 기존 구현과 사용자 변경은 그대로 두고 제품 UI 여섯 가지만 손봤다.
항목별 근거는 `docs/UI_SPEC_STATUS.md` 맨 아래 '덧붙임 (45.24)' 표에 있다.

## 고친 것

| # | 무엇 | 어떻게 |
|---|---|---|
| 1 | 색 패널의 높이와 스크롤 | 판을 세 자리로 갈랐다 — 머리줄(최근·색 추출·색 저장·닫기)과 탭은 고정, 견본만 스크롤(`flexShrink:1 · minHeight:0`, 아래 여백 16). 예전에는 판 전체가 한 스크롤이라 마지막 견본을 보러 내려가면 최근 색과 탭까지 밀려 올라갔다. 고정 도구 줄은 원래 판 바깥이다(`dock.bottom = BASE_H`) |
| 1 | 흰 견본 | 밝은 색에만 또렷한 테두리(`T.lineStrong`). 흰 견본이 빈칸처럼 보이지 않는다 |
| 1 | 검토 PNG 의 잘림 | 원인을 나눴다. ① 렌더러가 스크롤 영역을 펼쳐 그린 뒤 판 높이로 자르는 것 — 앱에서는 스크롤로 닿는다. ② 제품이 판 전체를 한 스크롤로 묶어 둔 것 — 이것만 고쳤다 |
| 2 | 패널 열었을 때의 캔버스 | **임시 맞춤 보기는 하지 않는다.** 기존 기능부터 확인했다: 엔진 `zoom` 은 `Math.max(1, …)` 라 1배보다 작게 줄지 않고, 캔버스 틀은 정사각 고정이며 `convenience-test:217` 이 '패널을 열어도 캔버스 자리·크기 그대로'를 지킨다. 새 확대 체계를 만들지 않고 **판 높이 축소 + 내부 스크롤**로 갔다 — 색 판이 덮는 비율 0.50 → **0.44**. 논리 캔버스 크기·획 좌표·저장 그림은 건드리지 않았다 |
| 3 | 도구 이름 | `집기` → **색 추출**, `담기` → **색 저장**(저장된 상태는 `저장됨`). 지우개·채우기에도 이름을 붙였다 — 같은 줄의 펜·색·선택에는 이름이 있어 세 칸만 규칙이 달랐다(45.6차 판단을 정정). 이름은 모두 하는 일과 대조했다: 색 추출 = `eyedrop`, 색 저장 = `saveUserColor` → `userPalette` |
| 3 | 노랑과 테두리 | 노랑 = 지금 그리는 도구 하나. 열린 보조 패널은 테두리 + 펼침 화살표 |
| 4 | 상단 배치 | 45.5차 주석은 과거 선택의 근거일 뿐이라고 적었다. 이번에는 캔버스를 위해 한 줄을 유지하되, 모드 묶음과 보조 묶음의 **실제 배치 폭**을 재어 넘치면 두 줄로 바꾼다(`tabsW + aidsW + 12 > headW`). 글자 크기나 손가락 자리는 줄이지 않는다 |
| 5 | 홈 표현 가이드 | 미리보기 세 칸에 실제로 연결되는 감정 이름(안녕·신나·잘 자). 칸 크기는 그대로, 설명은 더하지 않았다 |
| 5 | PRO 비교 그림 | 서로 다른 마스코트 두 장(276×306 · 103×132)을 **같은 그림 한 장**으로 바꿔 같은 캐릭터·같은 86×86. 차이는 앱이 그리는 표시가 말한다 — 왼쪽은 그림 전체, 오른쪽은 흔드는 손 하나. 가격·혜택·결제 정책은 건드리지 않았다 |

## 검토 렌더 도구에서 고친 것 (제품 아님)

CSS 는 `border-style` 이 없으면 두께를 무시한다. 이것을 옮기지 않아 **지금까지 검토 그림에서 모든 테두리가 빠져 있었다**. 한쪽 두께만 준 경우 나머지 변을 0 으로 못 박는 것까지 함께 고쳤다(그러지 않으면 CSS 가 기본 두께를 넣어 없던 네모가 생긴다).

## 구분

- 위 그림은 모두 **대체 렌더**다. 실제 App 을 그려 노드와 스타일을 옮긴 것이고, 그림과 캔버스는 실제 번들 PNG·실제 엔진 출력이지만 **실기기 캡처가 아니다**.
