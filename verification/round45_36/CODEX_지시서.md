## 0. 기준과 우선순위

1. **사용자 승인 시안**과 사용자 직접 지시가 최우선이다.
2. 45.35 구현(`verification/round45_35/README.md`)은 **출발점**이다. 기준이 아니다.
   45.35 구현자가 시안과 다르게 둔 곳은 사용자 승인을 받은 적이 없으므로 **시안으로 되돌리는 것이 기본**이다.
   다르게 유지하려면 실제 기능·접근성 근거(측정값)를 보고서에 제시한다.
3. 사용자 인계문은 45.34 기준이라 한 회차 뒤처져 있다. 인계문의 LOCKED(정책·권한·데이터 보존)는 그대로 유효하고,
   구현 상태 설명은 이 지시서가 대신한다.

### 판단 권한
- 승인 시안과 이미 승인된 방향 안에서 풀리는 디자인 판단(간격·정렬·크기·배치·상태 표현 등)은 **코덱스가 결정하고 근거를 보고**한다.
- 사용자에게 묻는 것은 두 경우뿐: ① 새 정책(무료/PRO·결제·움직임 구성 등)이 필요할 때, ② 승인 시안과 사용자 지시가 실제로 충돌할 때.
  이때도 막힌 항목만 보류하고 나머지는 진행한다.

## 1. 기존 구현의 취급 — 재사용하되, 결함과 시안 차이는 수정

45.35 까지의 구현은 **버리고 새로 만들지 않는다.** 구조·부품·데이터 경로를 재사용한다.
그러나 **"이미 구현됐다"는 이유로 수정 대상에서 빼지 않는다.** 왼쪽 조절대와 브러시 창도 §3 의 확인된 결함·시안 차이가 있으면 고친다.

| 기존 구현 | 재사용할 것 | 이번에 고칠 수 있는 것(§3 연결) |
|---|---|---|
| 왼쪽 세로 조절대 `VSlider`·`RailBubble` (`painter.tsx:209-261`) | 부모 비재렌더·끄는 동안 WebView 메시지 0·손 뗄 때 1회 반영 구조 | 위치·정렬(G1), 판과의 겹침(G2), 입력 좌표 방식(G19), 시각 세부(시안 대조) |

## 2. 선택 상태 규칙 — 역할별로 구분하고, 같은 역할끼리 통일

전부 같은 모양으로 만들지 않는다. 역할마다 하나의 규칙을 정하고, 그 역할의 모든 곳이 같은 색·형태·강조를 쓴다.
기준은 시안(특히 오른쪽 「선택 상태」 카드: 기본 / 선택 / 누르는 중 / 비활성)이다.

| 역할 | 어디 | 시안의 표현(기준) |
|---|---|---|
| **탭**(같은 화면의 보기 전환) | 그리기/움직이기, 브러시 선·채색·질감·효과, 색 직접 선택/팔레트 | 굵은 글자 + 노란 밑줄. 배경 없음 |
| **도구 버튼**(지금 쓰는 도구) | 펜·지우개·채우기·선택 | 연노랑 배경 + 짙은 아이콘·글자. 누르는 중=회색 배경, 비활성=옅은 아이콘 |
| **즐겨찾기 칸** | 하단 브러시 3칸 | 연노랑 면 + 짧은 노란 밑줄(시안 하단 '펜') |
| **목록 행**(여럿 중 하나) | 브러시 목록, 레이어 목록 | 행 전체 연노랑 + (브러시) 오른쪽 체크. 행 외곽선 없음 |
| **판 여는 머리 버튼**(참고·레이어·문구) | 머리 오른쪽 | 시안은 아이콘 위 작은 글자. 열린 상태 표현은 도구 버튼 규칙을 따르되 크기에 맞게 |
| **옵션 선택**(약/중/강 같은 값 고르기) | 브러시 세부 설정 등 | 시안에 직접 예시 없음 → 위 규칙 중 가장 가까운 역할을 골라 적용하고 이유 보고 |
| **효과 선택 카드** | 움직이기 효과 | 시안에 직접 예시 없음 → 즐겨찾기 칸 또는 도구 버튼 규칙 중 하나로 통일하고 이유 보고 |

규칙은 `src/components/ui.tsx` 등 기존 공통 부품에 **역할별 부품/토큰**으로 두고 각 판이 가져다 쓴다. 판마다 스타일을 복사하지 않는다.
판 머리는 역할이 같으므로 한 형식(제목 + 보조 동작 + 닫기 ×)으로 통일한다. 버튼은 주 동작(노랑 채움) / 보조(흰 바탕 얇은 테두리) / 아이콘 도구(테두리 없음) 3단 위계.

**G1 — 조절대가 캔버스가 아닌 빈 공간 옆에 있음 / 공간 낭비**
- 근거: R+D `screens/draw-base.png` — 390×844 에서 정사각 캔버스 위아래로 각 약 140dp 여백, 조절대 두 개가 작업 영역 전체 높이에 퍼져 불투명도 조절대가 여백 옆에 놓임. 시안은 조절대가 종이 옆.

**G19 — 조절대 끊김**
- 근거: **U** 사용자 "스무스하게 조절이 아니고 렉걸린거처럼 뚝뚝 끊김"(45.34 빌드). S `VSlider` 가 `onResponderMove` 의 `nativeEvent.locationY` 사용 — 손가락이 뷰 밖으로 나가거나 터치 대상이 바뀌면 값이 튈 수 있음(**가설**). 45.35 는 메시지 수만 쟀고 부드러움은 미검증.
- 수정 조건: `locationY` 의존 제거(예: `pageY` − 측정한 트랙 위치). 트랙 밖으로 나가도 값이 끝에서 멈추고 튀지 않음. 끄는 동안 저장·전체 갱신·WebView 메시지 없음 유지. 지연(debounce·setTimeout)으로 가리지 않음. 마지막 값이 다음 획에 반영.
- 검증: 트랙 밖 이동·빠른 왕복 입력 시퀀스 검사. 드래그 한 번의 렌더 횟수·이벤트당 JS 처리 시간을 **측정 환경 명시**해 전후 비교(개발 PC 수치를 기기 성능으로 일반화 금지). 실기기 불가 시 "실기기 미검증" 유지.

**G20 — 확대·이동 상태 보존 검사 부재**
- 근거: S/45.35 README §2-3 은 크기·배율 유지만 언급. **U** 사용자 "펜툴을 열면 캔버스가 무너짐이 살짝 있음".
