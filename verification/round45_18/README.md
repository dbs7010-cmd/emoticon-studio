### 배경은 진짜 투명이다
- 네 모서리와 가장자리 표본 모두 `rgba(0,0,0,0)`. **검정 픽셀이 아니라 알파 0** 이다. 보는 곳의 바탕색이 비쳐 흰 배경처럼 보인 것이다.
- 전체 1,572,516px 중 **72.6% 가 완전 투명**, 완전 불투명은 0.3%.
- `a>16 && 밝기>200`(불투명 흰색) 픽셀이 **시트 전체에 0개**다 → **몸 안쪽에 흰 채움이 없다. 원래부터 선만 있는 그림이다.**
- 그래서 **배경 제거를 하지 않았다.** 알파를 단 1비트도 건드리지 않았으므로 '흰 몸 내부까지 일괄 투명화'는 애초에 일어나지 않았다.

## E. 해상도 판정 — 시안이다, 최종 납품 PASS 가 아니다

| | 계약(45.17) | 실제 |
|---|---|---|
| 비율 | 1:1 | 1:1 ✓ |
| 바탕 | 투명 | 투명 ✓ |
| 글자 | 없음 | 없음 ✓ |
| 납품 권장 | 360×360 | **132×132 (37%)** ✗ |
| 마스터 | 1024×1024 | **132×132 (13%)** ✗ |

**최종 납품 PASS 를 선언하지 않는다.** 추출본은 시안으로 보존하고 연결만 했다.

### 재제작이 필요한 항목
1. **다섯 장 모두 다시** — 칸당 최소 360×360, 마스터 1024×1024 로. 지금 파일을 키우는 것으로는 해결되지 않는다.
2. **시트 방식 자체의 한계** — 9×9 한 장에 몰아 담으면 칸당 해상도가 시트 크기의 1/9 이 된다. 4096px 시트여야 칸당 455px 이 나온다. 낱장으로 받는 편이 확실하다.
3. **흰 채움 여부 결정** — 지금은 선만 있어 어두운 바탕에서 속이 비친다. 앱의 카드·참고 창은 밝은 바탕이라 지금도 무방하지만, 몸 안쪽을 흰색으로 채울지는 **미정**이다.
4. **손실 압축 잔털** — 원본이 lossy WebP 라 선 가장자리에 옅은 알파 잔털이 남는다(밝은 바탕에서는 보이지 않는다). 무손실 PNG 로 받으면 사라진다.

**연결한 이유**: 45.18 지시의 연결 관문은 "선이 읽히지 않거나 배경 제거가 그림을 손상시키면 연결하지 말라"이고, 둘 다 해당하지 않는다(선 또렷 · 배경 제거 자체를 하지 않음). 해상도 부족은 '납품 PASS 선언 금지' 항목으로 따로 처리했다. 큰 그림이 오면 **파일만 같은 이름으로 갈아 끼우면 된다** — 코드 변경이 필요 없다.
