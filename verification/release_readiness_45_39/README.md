## 2. 앱 화면 (`screens/`)

### 2-1. 실제 앱 화면을 찍지 못한 이유
이 PC에서는 실제 앱을 띄울 수 없었다.
- 연결된 안드로이드 기기가 없다(`adb devices` 0대).
- 에뮬레이터는 하드웨어 가속이 없어 실행할 수 없다(`HypervisorPresent=False`, `emulator -accel-check`: hypervisor driver 미설치). 켜려면 관리자 권한과 재부팅이 필요한 **시스템 설정 변경**이라 하지 않았다.
- 있는 가상 기기(`arm_test`)는 arm64 이미지라 이 PC(x86_64)에서 실행되지 않는다(45.9 기록과 같다).

### 2-2. 이 폴더의 화면은 '대체 렌더'다
- 만드는 법: 실제 소스(`App.tsx` · `painter.tsx`)를 테스트 렌더러로 그려 나온 노드와 스타일을 HTML로 옮기고(`scripts/_screens.cjs`, 390×844), Edge로 찍었다(2배 해상도).
- 그림 캔버스 안은 실제 그리기 엔진 견본 이미지다. 투명 부분의 체크 무늬는 렌더 도구의 표시이고, 앱에서는 흰 종이로 보인다.

**실제 앱과 다를 수 있는 점:**
- 안드로이드 글꼴 측정·줄바꿈
- 안드로이드 레이아웃 측정 차이(FAIL-027)
- 스크롤 위치
- 애니메이션
- 결제 창

**홍보용 스크린샷으로 쓰면 안 된다.**

### 2-3. 영상 — 촬영 불가
'새 그림 → 움직임 적용 → 저장 → 재열기 → 출력' 영상은 §2-1과 같은 이유로 **찍지 못했다.** 대체 렌더로 만든 동영상은 실제 앱처럼 보일 수 있어 만들지 않았다.

**대신 확인한 것(자동 검사, 실기기 아님):**
- `e2e-test`: 계획 → 그리기 → 저장 → 재시작 → 검수 → 내보내기 → 묶음 다시 열기
- `motion-v1-test`: 효과 선택 → 저장 → 재시작 복원
- `export-test`: ZIP 구조 · CRC · 제출 형식

**실제 영상이 필요하면:** 폰의 기본 **화면 녹화**로 최신 APK에서 찍는 방법이 가장 빠르다(개발자 모드 불필요). 촬영 순서는 §7에 적었다.

## 7. 실기기 영상 촬영 순서(사용자용, 약 1분)

1. 최신 APK(`f8cbaa7`)를 설치하고, 폰 빠른 설정의 **화면 녹화**를 켠다.
2. 홈 → '새 이모티콘' → 세트 만들기 → 01번 칸에 캐릭터를 간단히 그린다.
3. '움직이기' 탭 → '통통'(무료)을 고르고 세기를 조절한다.
4. '저장' → 캔버스 위 안내에서 '다음 칸' 대신 '뒤로'로 보드에 나간다.
5. 01번 칸을 다시 열어 그림과 움직임이 그대로인지 보여 준다.
6. 보드 → '내보내기' → 파일 묶음 만들기 → 공유 창까지.

**주의:** 이 APK는 **내부 검수 빌드**다. 설정의 검수용 PRO 스위치가 영상에 나오지 않게 한다. 홍보 영상은 출시 구성 빌드로 다시 찍는 것이 맞다.
