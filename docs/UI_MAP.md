## C. 조사로 확인한 것 (명세가 확인을 요구한 항목)

| 명세 | 확인 결과 |
|---|---|
| E10 `완성·다음` 이름이 정직한가 | **정직하다.** `save('complete')` → `saveFinal(..., complete)` 이 `done:true` 로 표시하고 저장한 뒤 다음 칸으로 간다. 빈 캔버스면 스스로 `stay` 로 낮춰 완성으로 세지 않는다. **이름을 바꾸지 않는다.** |
| 가이드 → 프로젝트 선택 정책 | `startFromGuide` 가 **가장 최근 세트의 다음 빈 칸**을 연다. 세트가 없으면 새로 만들고, 칸이 다 찼으면 보드를 보여 주고 사용자가 고르게 한다. **덮어쓰기·자동 생성으로 바꾸지 않는다.** |
| 새 칸 기본 레이어 수 | **1장.** HTML 시안의 '레이어 2' 는 시안 수치일 뿐이다. |
| 참고의 출력 제외 | 엔진 `save`·`buildLoop` 가 `layers` 만 합친다. 썸네일은 저장된 완성 그림을 쓴다. **정책 유지.** |
| 자동저장·token·1.5초·20초 | 45.12·45.13 정책 그대로. **이번 UI 작업으로 바꾸지 않는다.** |

## D. NEEDS_DECISION (코드에 없어 이번에 만들지 않음)

| 명세 항목 | 왜 보류인가 |
|---|---|
| S01 빈 칸 `+` 표시 | 현재 보드는 빈 칸도 번호 칸으로 그린다. 표시만 바꾸는 것은 가능하나 **빈 칸 탭 동작이 기존과 같아야** 하므로 확인 뒤 별도 처리 |
| T01 `사용 방법` 도움말 | 도움말 화면이 코드에 없다. **버튼만 만들지 않는다** |
| X02 `저장`/`파일 열기` | 현재는 `공유하기`만 있다. 시스템 저장 경로 반환이 없어 **발명하지 않는다** |
| E05 참고 창 크기 조절 핸들 | 현재 창은 고정 폭이다. 폭 clamp 는 이번에 적용, **사용자 리사이즈 핸들은 보류** |
| H03 새 세트 화면 | 현재는 화면 없이 바로 세트를 만든다(`createNewProject`). **빈 세트 생성 시점을 바꾸지 않는다** |

## E. 충돌 보고

- **색 토큰**: 명세 §2 표를 **그대로 적용했다**( ·  ·  ·  ·  ·  ·  · ). 지금까지의 따뜻한 크림 계열( ·  · )에서 **차가운 회색 계열로 바뀐다** — 기기에서 눈에 띄는 변화다.
  - 과거 라운드에 **브랜드 변경 금지** 지시가 있었으나, 명세가 색 값을 표로 직접 준 최신 지시라 그 표를 따랐다. **로고·공식 캐릭터·가격·약관은 건드리지 않았다.**
  - 명세 표에 없는 따뜻한 토큰(··)은 홈 창작 표면 하나에만 쓰이므로 **강조 면으로 남겼다**(명세도 ·· 같은 색 면을 허용한다).
  - 이 판단을 되돌리려면  의 토큰 한 벌만 되돌리면 된다.
