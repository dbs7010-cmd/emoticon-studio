## 45.13 — 실기기 검수 한 장 (먼저 이것부터, 2026-09-21)

기기가 생기면 이 한 장만 따라 하면 된다. 아래 명령은 추정이 아니라 `package.json`·`app.config.js`·`scripts/device-qa.cjs`·`docs/RELEASE_SIGNING.md`·`docs/PROJECT_STATE.md`(16차 빌드 기록)에서 확인한 값이다.
**Expo Go(`npm run android` = `expo start --go --android`)는 검수 근거로 쓰지 않는다** — 이 앱은 결제(`expo-iap`)와 `expo-dev-client` 를 쓰는 네이티브 빌드다. 검수는 아래 release APK 로 한다.

### 0. 앱을 켜는 정확한 명령 (PowerShell)

```powershell
# ① 빌드 환경(한글 사용자 이름 때문에 ASCII 경로가 필요하다)
$env:JAVA_HOME = "C:\Program Files\Unity\Hub\Editor\6000.3.23f1\Editor\Data\PlaybackEngines\AndroidPlayer\OpenJDK"
$env:ANDROID_HOME = "C:\Android\Sdk"; $env:ANDROID_SDK_ROOT = $env:ANDROID_HOME
$env:GRADLE_USER_HOME = "C:\gradle-home"; $env:TEMP = "C:\build-temp"; $env:TMP = "C:\build-temp"
$env:EMOTICON_INTERNAL_REVIEW = "1"            # 검수용 PRO 스위치가 들어간 빌드
$env:EMOTICON_ALLOW_DEBUG_SIGNED_RELEASE = "1" # 업로드 키 없이 release 를 만들 때만

# ② android/ 는 저장소에 없다(gitignore). 없으면 먼저 만든다
npx expo prebuild --platform android

# ③ APK 빌드 (arm64 기기 기준)
Push-Location C:\Dev\emoticon-studio\android
.\gradlew.bat :app:assembleRelease --no-daemon -PreactNativeArchitectures=arm64-v8a
Pop-Location

# ④ 이 APK 가 어느 소스인지 기록
node scripts/source-id.cjs

# ⑤ 기기 연결(USB 면 생략 가능, 무선 디버깅이면 기기 화면의 페어링 코드로)
node scripts/device-qa.cjs --pair 192.168.0.x:PORT 123456
node scripts/device-qa.cjs --connect 192.168.0.x:PORT

# ⑥ 설치하고 켜기 (덮어쓰기 설치라 기존 작업을 지우지 않는다)
C:\Android\Sdk\platform-tools\adb.exe install -r android\app\build\outputs\apk\release\app-release.apk
C:\Android\Sdk\platform-tools\adb.exe shell am start -n com.emoticonstudio.app/.MainActivity

# (선택) 자동 러너: 설치 → 홈 → 그리기 → 굵기 → 색 → 문구 → 움직이기 → 보드 → 내보내기 캡처
node scripts/device-qa.cjs --run
```

`install -r` 는 덮어쓰기라 기존 세트·그림을 지우지 않는다. 데이터를 지우고 시작해야 한다면 그렇게 하기 전에 반드시 사용자에게 묻는다.

### 2. 브러시 · 지우개 · 핀치 확대 · 문구 · 키보드
| 행동 | 기대 결과 | 남길 캡처 |
|---|---|---|
| 브러시 → 펜·붓·연필로 각각 한 획 | 셋이 눈으로 다르다. 연필은 연하고 결이 보이며, 한 획 안에서 겹쳐도 고르게 연하다 | 세 획이 한 화면에 |
| 지우개로 일부 지우기 | 지운 자리만 사라지고 다른 장은 그대로 | 전 · 후 |
| 두 손가락 핀치로 확대·축소하고 그 상태로 그리기 | 배율 표시가 바뀌고 확대 중에도 획이 손가락을 따라온다. 패널을 여닫아도 배율이 유지된다 | 확대 상태 |
| 문구 → 입력 → 글씨체 기본·또박·도톰 | 키보드가 올라와도 입력칸이 가려지지 않는다. **도톰이 기본보다 굵으면서 '늘·루' 같은 글자 속이 막히지 않는다**(45.12 수정 — Android 글꼴에서는 아직 미확인) | 세 글씨체 각각 |
| 문구 색: 왼쪽 동그라미 · 견본 5개 · 팔레트 | 동그라미는 표시 전용이라 눌리지 않고, 팔레트만 색 화면을 연다 | 문구 패널 |

### 3. 레이어 추가·삭제와 부분 움직임

| 검수용 PRO 로 부분 움직임을 한 장에 걸고 그 장을 지우기 | 그 장의 부분 움직임만 사라지고 다른 장의 것은 남는다. 되돌리기로 장과 움직임이 함께 돌아온다 | 움직이기 패널 전 · 후 |

### 4. 저장 · 재열기 · 앱 재시작 복원
| 행동 | 기대 결과 | 남길 캡처 |
|---|---|---|
| 그리다가 닫기 → 같은 칸 다시 열기 | 그림·장 목록·문구·움직임이 그대로 | 재열기 화면 |
| 앱을 완전히 종료(최근 앱에서 밀어 닫기) 후 다시 실행 | 마지막 세트·칸이 복원되고 저장한 것이 그대로 | 재시작 직후 |
| 통신을 끊거나 기기를 바쁘게 만든 상태에서 저장 | 1.5초 뒤 캔버스에 '저장 중이에요', 20초까지 응답이 없으면 알림창이 뜨고 **잠금이 풀려 다시 그릴 수 있다** | 알림창 |
| 저장 공간을 거의 채운 뒤 저장(가능하면) | '저장하지 못했어요' 안내, 그림은 화면에 그대로, 기존 저장본 손상 없음 | 알림창 · 이전 칸 |

### 5. 실제 내보내기
| 행동 | 기대 결과 | 남길 캡처 |
|---|---|---|

| 문구가 있는 칸의 PNG | 글자가 칸 안에 들어오고(좌우 16px 규칙) 잘리지 않는다 | 해당 PNG |

### 6. PRO — 검수용과 실제 구매의 구분
| 구분 | 무엇을 확인하나 | 한계 |
|---|---|---|
| **검수용 PRO** (설정 › '검수용 PRO 켜기'. `EMOTICON_INTERNAL_REVIEW=1` 빌드에만 보인다) | PRO 기능(부분 움직임·두 모습·여러 칸 한 번에·고급 브러시)이 기능으로서 동작하는지 | 결제·복원은 **전혀 확인되지 않는다**. 이 스위치는 출시 구성에는 아예 없다 |
| **실제 구매·복원** | Play 결제 시트, 취소, 보류 결제, 재설치 후 복원, 다른 계정에서 '복원할 구매가 없어요', 해지 뒤 만료 | 내부 테스트 트랙 업로드 + 라이선스 테스터 계정 + 영수증 서버(`EMOTICON_RECEIPT_ENDPOINT`)가 있어야 한다. 항목은 아래 30차 절 |
| **출시 구성 확인** | `EMOTICON_INTERNAL_REVIEW` 없이 빌드한 APK 에 검수용 스위치가 보이지 않는지 | 코드 쪽 같은 검사는 `npm run release:check` |

결과는 항목 옆에 PASS/FAIL·기기·날짜로 적는다. 캡처는 `verification/round45_13/device/` 에 모은다(이미지는 저장소에 올라가지 않는다 — 경로만 남긴다).


사용자 결정(2026-09-14): 라운드마다 BrowserStack 으로 멈추지 않고, 개발이 더 진행된 뒤 실제 Android 기기에서 한 번에 확인한다.
여기 적힌 항목은 **자동 검사만 통과**했거나 **실기기에서 확인되지 않은** 것이다. 확인하면 결과(PASS/FAIL·기기·날짜)를 옆에 적는다.
검수 빌드는 그 시점 소스로 새로 만든다(기존 보존 APK 는 최신 코드가 아니다).
