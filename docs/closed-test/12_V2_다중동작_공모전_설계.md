# V2 준비 — 다중 동작 · 공모전/공지 (2026-10-05, EXPERIMENTAL)

> 상태: **EXPERIMENTAL — 설계와 검증용 계산만.** 앱 코드·릴리즈 빌드에 넣지 않았다(첫 패치 AAB 와 분리).

## 4. 다중 동작(움직이기 페이즈 2)

### 지금 있는 것(중복 확인)
| 기능 | 하는 일 | 한계 |
|---|---|---|
| 전체 효과(preset) 1개 | 그림 전체에 20개 중 하나(무료 6·PRO 14) | 한 번에 하나 |
| 부분 움직임(parts) 여러 개 | 레이어마다 회전·이동·크기, 동시에 | 끝없이 반복되는 파형 — '단계'가 없다 |
| 함께/차례로 + 시작 간격 | 부분마다 시작을 늦춤(delay) | 위상만 어긋날 뿐 모두 계속 움직인다(측정: 함께와 10/10 프레임 다름 — 동작은 함) |
| 두 모습 번갈아(alternate) | 레이어 묶음 A/B 를 시간마다 교대 | 단계 연결은 아님 |

→ **'등장 → 흔들기 → 손 흔들기'처럼 시간 순서로 다른 동작을 잇는 기능은 없다.** V2 의 실제 새 부분은 '단계(steps) 타임라인'이다.

### 데이터(제안, 기존 저장본 호환)
```
Motion.steps?: Array<{
  id: string;
  target: 'whole' | { layerIds: string[] };     // 전체 또는 지정 레이어
  effect: MotionPreset | PartEffect;              // 전체 효과 20종 또는 부분 효과(회전·이동·크기)
  duration: number;                               // 초, 한 번 재생 길이
  repeat: number;                                 // 1~4
  mode?: 'loop' | 'enter';                        // enter: 등장 효과를 '머무는 자세'에서 멈춤
  strength: number; speed?: number;
}>
```
- `steps` 가 없으면 지금과 똑같이 동작(옛 작품 그대로). 있으면 한 바퀴 = 단계 길이의 합.
- 미리보기·내보내기는 이미 같은 함수(deltaFor → composite)를 쓰므로, steps 도 deltaFor 안에서 시간 → 단계로 바꿔 계산하면 두 결과가 같다(이번 패치에서 프레임 대조 방법을 갖춤: `scripts/promo/motion-audit.cjs`).

### 검증용 계산(프로토타입) — `scripts/promo/multistep-prototype.cjs`
앱의 실제 식(presetDelta)으로 각 효과의 시작·끝이 정지 자세에서 얼마나 떨어져 있는지 쟀다(세기 0.5, 360px).
- 이어 붙이기 좋음(0px): shake · pulse · float · tilt · vanish · hop · nod · bow · sway · spin · punch · stretch
- 작은 전환 필요(2~11px): bounce · dance(10.8) · jitter(1.8) · shiver(2.2) → 단계 경계 0.1초 섞기
- 등장 계열(시작·끝이 칸 밖, 180~378px): pop · slide · peek · drop → **'enter' 모드(머무는 자세에서 멈춤) 필요.** 그대로 이으면 예시 타임라인(쓱 → 흔들기)에서 경계 튐 367px.

### 최소 UI(초보용)
움직이기 탭 › '단계로 만들기'(PRO) → 최대 3단계 목록. 단계마다 [효과 고르기] [대상: 전체/레이어] [길이 0.4~2초] [반복 1~4]. 순서는 길게 눌러 옮기기. 미리보기는 지금 캔버스 그대로.

### 남은 결정 · 검증
- PRO 범위에 넣을지(제안: PRO).
- 카카오 움직이는 이모티콘 프레임 수·길이 제한 안에 들어가는지 — 공식 규격 확인 후 단계 합계 상한을 정한다(지금 앱의 규격 값은 `src/constants/kakao-spec.ts`, 출처 표기 그대로 따름).
- 구현 후: 단계 경계 튐 0, 미리보기=내보내기 프레임 일치, 옛 작품 그대로를 자동 검사로.

## 5. 공모전 출품 · 공지칸

### 지금 있는 것
- 홈 공지 자리: `src/design/asset-slots.ts` `HOME_NOTICE {enabled, title, body, link}` — **앱 코드에 박힌 값**이라 바꾸려면 앱 업데이트가 필요하다. 지금 `enabled:false`(비공개 테스트 빌드에서는 같은 자리에 PRO 체험 안내가 대신 뜬다).
- 제출 준비: 내보내기 화면의 카카오 규격 점검(제출 준비 · 손볼 곳) + 파일 묶음(ZIP, WebP·PNG 프레임).
- 공모전 관련 접수·서버·출품 기록: **없음.**

### 두 가지를 나눈다
| | 외부 공모전 안내·제출 지원 | emoti 자체 공모전 접수 |
|---|---|---|
| 하는 일 | 공식 공모전 안내를 띄우고, 규격 점검 → 파일 묶음 → 공식 접수처 링크로 보냄 | 앱이 작품을 직접 받음 |
| 필요한 것 | 공모전 정보(주최·기간·규격·접수 링크)의 **실제 출처** | 접수 서버·저장소, 심사·연락 운영, 응모 약관, 개인정보 처리(수집 항목·보관·파기·위탁), 상금·저작권 규정 |
| 앱이 '출품 완료'라고 말할 수 있나 | **아니다** — 공식 접수처에서 사용자가 제출해야 함. 앱은 '파일 준비됨 · 접수처 열기'까지만 | 서버가 받았다고 응답한 경우에만 |

### 최소 흐름(외부 공모전 안내, 서버 없이 가능)
작품(세트) 고르기 → 규격 확인(기존 제출 준비 재사용) → 파일 묶음 만들기(기존) → '접수처 열기'(공식 링크) → 화면 문구 "접수는 공모전 사이트에서 직접 해 주세요".

### 공지칸 준비(제안)
- `HOME_NOTICE` 에 `startsAt`·`endsAt`(ISO 날짜) 추가 → 기간 밖이면 자리 없음, 링크는 https 만 열고 실패 시 안내(기존 동작).
- 원격으로 켜고 끄려면 공지 파일을 공개 주소(예: 이미 쓰는 GitHub Pages)에 두고 앱이 읽어야 한다 → 네트워크 요청이 생기므로 **개인정보처리방침·데이터 보안 갱신 필요.** 그 전에는 앱 업데이트로만 바꾼다.

### 사용자 결정이 필요한 것(이것만)
1. 첫 단계를 **외부 공모전 안내(서버 없음)** 로 할지, **자체 접수**까지 할지.
2. 외부 안내라면 올릴 공모전 정보의 출처(공식 링크) — 앱은 지어낸 공모전·일정·접수처를 넣지 않는다.
3. 공지를 앱 업데이트로만 바꿀지, 원격 공지 파일(네트워크 요청·방침 갱신)을 둘지.
