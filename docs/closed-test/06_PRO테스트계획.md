# PRO 테스트 계획 — 무료 테스트와 분리

## 0. 지금 사실(숨기지 않음)
- **실제 구매와 구매 복원은 한 번도 검증되지 않았다.**
  - 앱 코드와 가짜 스토어·가짜 서버 검사(`iap-test`·`server-test`·`pro-test`)만 통과했다.
  - 실제 Play 결제 창, 실결제, Play API 응답, 결제 확정(acknowledge), 복원, 재설치 복원은 **미검증**이다.
- 막힌 곳:
  - Play Console에 `pro_lifetime` 상품이 없다(가격 미확정).
  - 영수증 확인 서버가 배포되지 않았다(`server/verify-receipt.js` 코드만 있음).
  - 빌드에 서버 주소가 없다.
- 검수용 PRO 우회(`reviewUnlock`)는 **내부 검수 빌드에만** 있다. 출시 구성에서는 스위치가 그려지지 않고 저장된 값도 무효다(`review-pro-test`, `release-check` `internal_review_off`).

## 1. 무료 비공개 테스트 (1단계)
- 빌드: 출시 구성 + **구매를 닫은 구성**(`EMOTICON_PURCHASES=closed`, 코덱스 지시 C7). 검수용 우회는 없다.
- 테스터가 보는 것:
  - PRO 기능 소개는 보인다.
  - 구매·복원 버튼 대신 '이번 테스트 버전에서는 PRO 구매가 아직 열리지 않았어요'가 보인다.
  - PRO 효과 미리보기(내 그림으로 몇 초)는 된다. 넣기와 저장은 안 된다.
- 모집글·스토어 소개에도 '테스트 기간에는 PRO 구매가 열리지 않아요'를 적는다(01·02번 문서).
- **하지 않는 것:** 테스터에게 내부 검수 APK를 나눠 주는 것, PRO 코드를 나눠 주는 것.

## 2. PRO 결제 테스트 (2단계, 조건이 갖춰진 뒤)

**시작 조건(전부 필요):**
1. Play Console에 `pro_lifetime`(관리형 상품, 비소모성) 등록 · 가격 확정 · 활성화
2. 영수증 확인 서버 배포(HTTPS)
   - 서비스 계정에 Play Developer API 권한
   - 환경변수 `GOOGLE_SERVICE_ACCOUNT_JSON`·`ANDROID_PACKAGE_NAME`
   - 테스트 구매 허용 설정
3. 빌드: `EMOTICON_RECEIPT_ENDPOINT=https://…`, `EMOTICON_PURCHASES` 없음(정식 구성). `release-check` 전체 PASS
4. **라이선스 테스터** 등록. 테스트 결제는 실제로 청구되지 않는다.
5. 대상: 운영자와 라이선스 테스터만(내부 테스트 트랙). 1단계 무료 테스터 전원에게 열지 않는다.

**확인 항목:**

| # | 시나리오 | 기대 |
|---|---|---|
| P1 | 가격 조회 | 스토어 현지 가격이 보이고 구매 버튼이 켜진다 |
| P2 | 구매 성공 | 서버 확인 뒤 PRO. PRO 브러시·움직임이 열린다 |
| P3 | 구매 취소 | 아무것도 바뀌지 않고, 무료 기능은 그대로다 |
| P4 | 결제 보류(느린 결제 수단) | PRO가 되지 않는다. 확정되면 반영된다 |
| P5 | 서버 연결 실패 중 구매 | 확정하지 않는다(3일 안 미확정이면 Play가 자동 환불). 화면이 그렇게 말한다 |
| P6 | 구매 복원 | 같은 계정 다른 폰, 또는 재설치 뒤 '구매 복원'으로 PRO |
| P7 | 재설치 자동 복원 | 앱을 다시 설치하고 켜기만 해도 PRO |
| P8 | 오프라인 | 이미 산 PRO가 유지된다 |
| P9 | 환불(테스트) | PRO 종료, 기록 보존. **이미 넣은 PRO 효과는 재생·내보내기 유지** |
| P10 | 다른 계정 | PRO가 아니다 |

**결과 기록:** 시나리오마다 기기·계정 종류(라이선스 테스터)·결과·화면 녹화를 남긴다. 미확인 항목은 미확인으로 둔다.

## 3. 외부에 말하는 방식
- PRO 구매가 검증되기 전에는 SNS·스토어·모집글에서 **'PRO 구매 가능'을 말하지 않는다.**
- PRO 기능은 '준비 중 · 테스트 기간에는 구매가 열리지 않음'으로만 소개한다.
