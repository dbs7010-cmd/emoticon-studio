### 계정 연결 · 권한 점검
- 회원 식별자 = `회사:회원번호`(예 `kakao:…`, `naver:…`, `google:…`). **회사가 다르면 다른 계정**이다 — 자동 연결 없음(이메일을 받지 않으므로 같은 사람인지 알 수 없다).
- 작품은 **기기 안**에 있어 로그인과 무관하게 남는다. 계정에 묶이는 것: 작가명 · 클라우드 백업 · 공모전 접수 · PRO 구매 연결.
- PRO 구매: 한 Play 구매 토큰은 **처음 확인한 emoti 계정 하나**에만 묶인다(`purchases/{해시}`). 다른 회사로 로그인해 구매 복원하면 "처음 산 계정으로 로그인해 주세요"로 거절 → **결정 필요(아래)**.
- 비밀번호: 앱·서버 모두 받지 않음(각 회사 로그인 화면에서만). 회사 접근 토큰은 서버가 회원번호만 읽고 버린다(저장 안 함). 앱에는 Firebase 로그인 유지 토큰만 앱 전용 저장소(AsyncStorage)에 있다.
- 앱이 PRO 를 만들 수 있나: **서버 쪽은 불가** — `users` 문서 앱 쓰기 금지(규칙), 클라우드 백업은 서버가 준 PRO 만, 구매는 서버가 Play 에 직접 확인. **기기 쪽 편집 기능**은 기기 저장 파일의 확인 표시로 열리므로 루팅 기기에서 파일을 고치면 열 수 있다(일반적인 한계 — 서버 기능은 열리지 않음).

## 2. 실행 계획 (의존 순서)
1. 상태표·계획(이 문서) → 커밋
2. **제작 편의**(결정 불필요 — 바로 진행)
   - A 부분 움직임: 중심점 자동 추정(레이어 그림 상자 중 몸 쪽 가장자리, 고칠 수 있음) · 출발점(손 흔들기·귀 까딱·통통) · 중심점 버튼 밖으로 · 레이어 나누러 가기
   - B 바로 쓰는 조합 3개(등장→인사 · 놀람→떨기 · 폴짝→신남) — 단계 엔진 그대로, 고른 뒤 단계 화면에서 고침
   - C 이전 칸으로 시작 시 **그 칸의 움직임도 함께**(빈 칸일 때만, 되돌리기 한 번으로 움직임만 뺌)
   - D 무료 사용자도 조합을 **자기 그림으로 미리보기**(저장 시 PRO 안내 · 무료로 저장하면 원래대로) · 구매 화면을 같은 그림의 기본·부분·단계 비교 영상으로
3. 안정성: 실제 출력 파일(애니메이션·부분 움직임·단계 칸) 규격·잘림·파일명 에뮬레이터 확인 · 저장·강제 종료·재실행 보존
4. 동일 그림 작업 기록 4종(에뮬레이터, 조작 수·화면 전환 수)
5. 검사 → 커밋·원장 → 빌드(업로드 기록 확인 후 versionCode) → 보고
