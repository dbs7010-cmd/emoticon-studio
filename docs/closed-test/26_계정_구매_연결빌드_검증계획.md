# 26. 계정·구매 연결 · 연결 빌드 검증 계획 (2026-10-15)

근거는 코드(파일:줄 기준 내용)다. 실제 서비스에서 같은 사람이 다른 로그인으로 들어와 본 시험은 **아직 없다**.

## 1. 두 종류의 계정 — 구분

| | Google Play 계정 | emoti 회원 계정 |
|---|---|---|
| 무엇 | 휴대폰의 Play 스토어에 로그인한 Google 계정 | 앱에서 고른 로그인: 카카오 · 네이버 · 구글 |
| 식별자 | Play 가 관리(앱은 모름) | `회사:회원번호` (예 `kakao:5132…`). 회사가 다르면 **다른 회원** |
| 결제·영수증 | 여기서 결제되고 구매 기록이 남음 | 결제하지 않음 |
| 묶이는 것 | PRO 구매 토큰 | 작가명 · 서버 PRO(`users/{uid}.pro`) · 클라우드 백업(`backups/{uid}`) · 공모전 접수 · 구매 연결 기록(`purchases/{토큰 해시}.uid`) |

앱 로그인에서 '구글'을 골라도 Play 계정과 자동으로 같은 것이 아니다. 같은 Google 계정일 수는 있지만 서버는 둘을 잇지 않는다.

## 2. 같은 사람이 다른 로그인으로 들어오면 (지금 코드)

예: 카카오로 로그인해 PRO 를 산 사람이 같은 휴대폰에서 로그아웃하고 구글로 로그인.

| 대상 | 결과 | 코드 근거 |
|---|---|---|
| 기기 안 작품 | **그대로 보인다.** 작품은 기기 저장소에 있고 회원과 무관 | `storage.ts` — 저장소에 uid 없음 · 탈퇴 안내 '이 기기 안 작품은 그대로예요' |
| 기기의 PRO 편집 | 로그아웃해도 바로 꺼지지 않는다(기기 저장 이용권). **다음 앱 실행 때** Play 의 구매를 새 회원으로 확인 → 서버가 '다른 emoti 계정' 거절 → 기기 이용권을 끝냄(기록은 남아 만든 PRO 움직임은 재생·내보내기 됨) | `App.tsx` 시작 재확인 → `pro.ts refreshEntitlement` 거절 시 `end()` |
| 구매 복원 버튼 | 거절: **'이 구매는 다른 emoti 계정에 연결되어 있어요. 처음 산 계정으로 로그인해 주세요.'** — 이번에 이 문장이 화면까지 가도록 고침(전에는 일반 문구 '이 구매를 확인하지 못했어요') | `purchase.js` 73·80줄 · `pro.ts confirm` reason |
| 서버 PRO · 클라우드 백업 | 새 회원(구글)은 무료 회원 → 백업 불가, 카카오 쪽 백업은 보이지 않음 | `users/{uid}` · `backups/{uid}` 경로 · 저장소 규칙 |
| 작가명 · 공모전 접수 | 카카오 회원 것. 구글 회원에는 없음(작가명 새로 정해야 함) | `artistNames` · `submissions` uid 기준 |
| 다시 카카오로 로그인 | 구매 복원 → 같은 uid 라 통과 → PRO 다시 켜짐 · 백업 다시 보임 | `purchase.js` 73줄(같은 uid 면 통과) |

### 이번에 고친 위험 (코드로 찾음, 자동 검사로 확인)
- 앱을 막 열어 로그인을 되살리는 중(로그인 증명 없음)에도 시작 재확인이 서버에 물었다. 서버는 '로그인한 뒤…'로 거절하고, 앱은 이 거절을 '구매 없음'처럼 처리해 **산 사람의 PRO 를 끌 수 있었다.** → 로그인 증명이 없으면 묻지 않고 그대로 둔다(`signed-out`). `iap-test` 에 '로그인 전이면 저장된 PRO 유지' · '로그인 전 복원은 로그인 안내' 추가.

### 악용·오류 여지 (단정하지 않음 — 알려진 것)
- 기기 편집 PRO 는 기기 저장 파일의 확인 표시로 열린다 → 루팅 기기에서 파일을 고치면 편집 기능은 열릴 수 있다(서버 기능 — 백업·서버 PRO — 은 열리지 않음).
- 탈퇴하면 구매 연결 기록도 지워진다(`deleteMyAccount`). 같은 Play 구매를 다른 emoti 회원에 **다시** 묶을 수 있다 — 동시에 둘은 아니지만, 한 Play 계정을 여러 사람이 쓰는 가정(가족 기기)에서 옮겨 다닐 수 있다.
- 운영 서버는 지금 **라이선스 테스터의 테스트 구매도 PRO 로 받는다**(`.env.emoti-18d80` `PURCHASE_ACCEPT_TEST=true`, sandbox 표시). 테스터 목록에 있는 사람만 테스트 구매를 할 수 있지만, 정식 출시 전에 끌지 결정이 필요하다.
- 시작 재확인은 한 번뿐이라, 다른 로그인으로 바꾼 직후 그 실행 동안은 기기 PRO 가 남아 있다.

## 3. 계정 연결 — 제안 (구현하지 않음)
자동 병합·PRO 이전은 만들지 않는다. 가능한 길:

| 안 | 본인 확인 | 작업 | 위험 |
|---|---|---|---|
| A. 연결하기(로그인 둘 다 통과) — 지금 로그인 상태에서 '다른 로그인 연결' → 두 번째 회사 로그인을 **그 자리에서 한 번 더 통과**해야 연결. 서버는 두 uid 를 한 사람으로 기록하고 PRO·백업을 함께 본다 | 두 회사 로그인 모두 통과 | 서버 연결 기록·규칙·탈퇴 처리·화면, 중간 | 연결 해제·탈퇴 순서 설계 필요 |
| B. 관리자 수동 이전 — 문의 → 관리자 화면에서 Play 주문 번호(GPA.…)와 두 회원을 확인한 뒤 구매 연결을 옮김 | 주문 번호 + 두 계정 로그인 캡처 | 관리자 함수 하나 + 기록, 작음 | 사람이 확인 — 실수 여지 |
| C. 지금 그대로 + 안내 강화(이번에 거절 문장 표시) | — | 끝남 | 사용자가 어느 회사로 샀는지 기억해야 함 |

추천 순서: 지금은 C(완료) → 문의가 생기면 B → 사용자가 늘면 A.

### 연결 전에 잘못 로그인했을 때 복구 동선 (지금 가능한 것)
1. 내 정보 › 계정 › **로그아웃** (작품은 그대로).
2. 처음 산 회사로 다시 로그인.
3. PRO 화면 › **구매 복원** → PRO 켜짐, 백업 다시 보임.
4. 잘못 만든 회원이 필요 없으면 그 회원으로 로그인해 탈퇴(그 회원의 서버 데이터만 지워짐).
- 화면 개선 제안(미구현): 거절 문장에 '처음 산 회사'(카카오/네이버/구글)까지 알려 주기 — 서버가 `purchases` 의 uid 앞부분만 돌려주면 된다. 개인 정보(회원번호)는 보내지 않는다.

## 4. 검수 빌드 vs 연결 빌드 — 설정 차이

| 항목 | 검수 빌드 (`EMOTICON_INTERNAL_REVIEW=1`) | 연결 빌드 (vc9: `FIREBASE_CONFIG` + `LOGIN=kakao,naver,google` + `PURCHASES=closed` + `PRO_TRIAL=1`) |
|---|---|---|
| 서버 연결 | 없음(Firebase 설정 없음) | 운영 `emoti-18d80` |
| 로그인 | 없음 — 바로 홈 | **필수** — 카카오·네이버·구글 시작 화면 |
| PRO | '결제 없이 검수용 PRO 켜기' 스위치(저장소 `reviewUnlock`) | 체험 PRO(빌드 값, 저장 안 함) — 모든 테스터 PRO |
| 결제 | 열림 구성이지만 영수증 서버 주소 없음 → 구매 확인 불가 | 닫힘('PRO 구매 준비 중') |
| 영수증 서버 주소 | 없음 | 없음(결제 닫힘이라 쓰지 않음) |
| 클라우드 백업 · 작가명 · 공모전 · 관리자 체험 PRO | 없음 | 있음(서버 권한 규칙 적용) |
| 업로드 | **하지 않음**(구성 검사가 closed+internalReview 를 막음) | Play 비공개 테스트용 |

**검수 빌드로 확인한 것은 '그리기·움직이기·PRO 화면 모양'뿐이다.** 로그인 이후 화면·서버 권한·무료/PRO 구분(서버 PRO, 백업 가능 여부)·체험 PRO 표시는 연결 빌드에서 따로 확인해야 한다.

## 6. 실기기 구매 시험 — 청구 없는 공식 방법부터
현재 설정(원장 §46, 운영자 보고): 상품 `pro_lifetime` 활성 · **라이선스 테스터 목록 '나'(1명)** · 서버 `PURCHASE_ACCEPT_TEST=true`.

1. Play Console › 설정 › **라이선스 테스트**: 휴대폰 Play 스토어 계정이 목록에 있는지 확인. 있으면 결제 창에 '테스트 카드, 청구되지 않음'이 보인다(실제 청구 없음).
2. 결제 열린 빌드가 필요하다(vc9 는 결제 닫힘). 비공개 테스트 트랙에 결제 열린 빌드(vc7 85bacc8 은 저장 상태, 또는 새 vc10)를 올리고, 그 트랙 테스터 목록에 휴대폰 계정을 넣는다.
3. **삭제 없이 먼저**: PRO 화면 › 구매 → 테스트 카드 → 'PRO를 시작했어요' → 같은 화면 **구매 복원** → 'PRO를 다시 켰어요'(재설치 불필요). 운영 DB `users/{uid}.pro.source=store, sandbox=true`.
4. 재설치 복원은 0번 전체 백업을 드라이브에 둔 **뒤에만**: 앱 삭제 → 설치 → 같은 회사 로그인 → 앱 시작 시 자동 복원 또는 구매 복원 → 전체 백업 되살리기.
5. 다른 로그인 시험: 구글로 로그인 → 구매 복원 → '이 구매는 다른 emoti 계정에 연결되어 있어요…' 문장 확인.

## 7. Console 제출 — 실제 막힘 문구 기준
- 운영자 캡처(10-13·10-15): 게시 개요 '**변경사항이 검토를 위해 전송되지 않음 · 문제 1개**' — 문제 내용 '**계정 세부정보 업데이트: 한국 개발자 추가 정보**'(사업자 등록 번호 · 전자상거래(통신판매업 신고) 번호 · 대행사/신고 기관).
- 통신판매업 신고 번호를 입력하면 **이 문제는 해결될 것으로 예상**하지만, Google 의 정보 확인 절차가 따로 있을 수 있어 제출 버튼이 바로 열린다고 단정하지 않는다. 입력 뒤 게시 개요의 '문제' 수가 0 인지 먼저 확인하고, 남아 있으면 그 문구를 알려 주면 다음 조치를 정리한다.
