# 25. 같은 그림으로 해 본 작업 4가지 — 기록 (2026-10-15)

- 기기: 에뮬레이터 emoti_promo_x86 (1080×2400, Android, `-gpu swiftshader_indirect`)
- 앱: 내부 검수 빌드(검수용 PRO 켜짐). **실제 서비스·실기기 결과가 아니다.** 결제·로그인 서버는 쓰지 않았다.
- 그림: 세트 '새 이모티콘 세트'의 고양이(몸 레이어 1 + 손 레이어 2), 칸 03 → 04
- 탭 수는 화면을 직접 누른 횟수다. 목록을 밀어 올린 횟수(스크롤)는 따로 적었다. 초보자 성공률이 아니다(시험자 1명 = 개발 쪽).

## 작업 1. 손만 흔들기

| 단계 | 탭 | 화면 변화 |
|---|---|---|
| 세트에서 빈 칸 열기 | 1 | 그리기 화면 |
| '이전 칸 그림으로 시작' | 1 | 그림 + 움직임을 함께 가져옴, 안내 '그림과 움직임을 함께 가져왔어요 · 되돌리기로 움직임만 뺄 수 있어요' |
| 움직이기 탭 | 1 | 효과 격자 |
| (스크롤 7번) | – | '부분만 움직이기'가 패널 맨 아래 |
| 부분만 움직이기 | 1 | 레이어 목록 |
| 가져온 옛 부분 지우기 | 1 | 복사해 온 칸일 때만 |
| 레이어 2 '움직이기 +' | 1 | **축이 몸 쪽 끝으로 자동으로 잡힘**, 안내 '중심점(축)은 몸 쪽 끝으로 잡았어요 · 다르면 옮겨요' |
| '손 흔들기' | 1 | 회전 25° · 속도 0.65, 손이 칸 안에서 흔들림 |
| 저장 | 1 | |

- 합계: 탭 8번(옛 부분 지우기 빼면 7번) + 스크롤 7번.
- 예전 흐름과 비교: 예전에는 부분을 넣으면 축이 그림 **한가운데**였다. 같은 그림의 칸 03(예전 흐름으로 만든 칸)은 팔이 칸 밖으로 휘둘러져 '칸 밖으로 나가요' 경고가 떴다. 고치려면 세부 펼치기 → 중심점 옮기기 → 캔버스에서 끌기 → 회전 고르기 → 크기·속도 슬라이더 2개가 더 들었다(탭 4번 이상 + 끌기 1번 + 슬라이더 2번).
- 실패·막힘: 없음. 불편: 스크롤이 길다(아래 '남은 불편').

## 작업 2. 등장 → 인사

| 단계 | 탭 | 화면 변화 |
|---|---|---|
| 부분 화면에서 뒤로 | 1 | 효과 격자 맨 위 |
| (스크롤 5번) | – | '조합' 줄이 효과 17개 아래에 있음 |
| '등장 → 인사' | 1 | 단계 화면이 열리고 1단계 쓱 0.6초 · 2단계 꾸벅 0.9초가 채워짐. 손 흔들기는 그대로 같이 움직임 |
| 저장 | 1 | |

- 합계: 탭 3번 + 스크롤 5번. 예전(단계 직접 만들기): 단계로 잇기 → 단계 추가 → 효과 고르기 → 단계 추가 → 효과 고르기 → 길이 조절 2번 = 탭 5번 + 슬라이더 2번.
- **발견 1 → 고침**: 조합이 효과 17개 아래에 있어 스크롤을 5번 해야 닿았다. → 묶음 칩에 **'조합'**을 더했다(누르면 효과 격자를 숨기고 조합 줄만 보인다). 이제 탭 2번(조합 칩 → 조합)으로 닿는다. (새 빌드에서 기기 확인 필요)
- **발견 2 → 고침**: 부분 움직임이 있는 칸에 **쓱(등장)**을 걸면, 들어오는 동안 손 레이어가 칸 밖에 있는 것을 '칸 밖으로 나가요' 잘림으로 셌다(부분 레이어만 등장 구간을 빼지 않았다). → 부분 레이어도 등장 구간을 뺀다. 회귀 검사 `anim-engine-test` 10번: 고치기 전 코드에서 실패, 고친 뒤 통과를 둘 다 확인.

## 작업 3. 여러 칸에 움직임 다시 쓰고 일부만 고치기

- 칸 04를 '이전 칸 그림으로 시작'으로 열자 칸 03의 **그림 + 움직임이 한 번에** 들어왔다(탭 1번). 그 뒤 부분 움직임만 바꿨다(작업 1).
- 같은 흐름의 자동 측정(`slot-repeat-test`): 예전 11탭 → 지금 6탭, **칸마다 탭 3번 감소**(색 확인 2탭 포함 기준).
- PRO 움직임을 무료 사용자가 복사하면: 그림만 가져오고 '이전 칸 움직임은 PRO라 빼고 가져왔어요'(자동 검사로 확인, 기기 확인 안 함).

## 작업 4. 저장 → 내보내기 → 다시 열기

| 단계 | 결과 |
|---|---|
| 내보내기 화면 | '움직이는 이모티콘 4 / 24칸 완성', 손볼 곳 1개 |
| **발견 3 → 고침** | '같은 그림 · 03, 04번 파일이 완전히 같아요'가 떴다. 04는 그림이 같지만 움직임이 다르다. 비교가 정지 그림 파일만 봤기 때문 → 움직이는 칸은 움직임·장 정보까지 같아야 같은 파일로 본다. `spec-test`에 '같은 정지 그림 + 다른 움직임은 중복 아님' 추가 |
| 파일 묶음 만들기 | 묶음 생성 성공, 공유 창에 `set-새-이모티콘-세트-j96hrb-20261015-091621.zip` |
| 강제 종료 → 다시 실행 | 홈 '4 / 24칸', 세트 화면 4칸 모두 남아 있고 썸네일이 움직임 |

- 묶음 **안쪽 파일**(GIF 장 수·크기·360×360·파일 이름)은 기기에서 꺼내 보지 못했다(출시 서명 빌드라 앱 폴더를 읽을 수 없음). 안쪽 규격은 자동 검사(`export-test`, `flow-test`, `spec-test`)로만 확인했다.
- 에뮬레이터 그래픽이 한 번 멈췄다(아래에서 위로 밀다가 최근 앱 화면이 열림). 그 직후 칸 03 썸네일이 깨져 '손볼 곳' 빨간 점이 떴고, 칸을 열어 다시 저장하자 정상으로 돌아왔다. 그림 데이터는 손상되지 않았다. 앱 문제인지 에뮬레이터 문제인지는 **확인하지 못했다**.

## 남은 불편 (고치지 않음)

- '부분만 움직이기' 입구가 효과 격자 맨 아래라 스크롤 7번이 든다. 위치를 옮기면 '캔버스 움직이기 배치'가 바뀌므로 사용자 결정이 필요하다(배치 변경 금지 지시).
- 세트 화면은 '4 / 32칸', 홈·내보내기는 '4 / 24칸'(움직이는 세트 기준)으로 숫자가 다르다.
