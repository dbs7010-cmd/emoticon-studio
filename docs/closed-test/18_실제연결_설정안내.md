# 실제 연결 설정 안내 — Firebase → 구글 → 카카오 → 네이버 (2026-10-10)

> 이 문서대로 운영자가 계정을 만들고 값을 넣으면, 서버 배포 → 실기기 실제 로그인·백업·공모전 검증으로 넘어간다.
> **비밀 값(Client Secret·서비스 계정 키)은 채팅·저장소에 넣지 않는다.** 터미널의 숨김 입력(Secret Manager)으로만 넣는다.
> 아래 `<프로젝트ID>` 는 1-1 에서 정해지는 Firebase 프로젝트 ID(예: `emoti-7f3a2`)로 바꿔 읽는다.
> 콘솔 메뉴 이름은 2026-10 기준이다. 화면이 바뀌어 메뉴를 못 찾으면 그 화면을 캡처해 주면 맞춰 안내한다.

## 미리 준비된 값(코드에서 정해진 것 — 그대로 쓴다)

| 항목 | 값 |
|---|---|
| Android 패키지 | `com.emoticonstudio.app` |
| iOS 번들 ID(나중) | `com.emoticonstudio.app` |
| 앱 돌아오는 주소(스킴) | `emoti://auth` (앱 안 고정 — 콘솔에 넣지 않음) |
| 로그인 시작 주소 | `https://<프로젝트ID>.web.app/auth/start` |
| 구글 Redirect URI | `https://<프로젝트ID>.web.app/auth/callback/google` |
| 카카오 Redirect URI | `https://<프로젝트ID>.web.app/auth/callback/kakao` |
| 네이버 Callback URL | `https://<프로젝트ID>.web.app/auth/callback/naver` |
| 서비스 URL / 사이트 도메인 | `https://<프로젝트ID>.web.app` |
| 웹 계정 삭제 페이지(Play 데이터 보안에 적을 주소) | `https://<프로젝트ID>.web.app/account/` |
| 관리자 페이지 | `https://<프로젝트ID>.web.app/` |
| 서버 지역 | `us-central1` (무료 한도가 미국 리전에만 있음 — 비용표 19번 문서) |
| 받는 회원 정보 | 회원 식별 번호만(카카오 회원번호 · 네이버 고유 ID · 구글 sub). 이메일·이름·전화번호 요청 안 함 |

> 바뀐 점(2026-10-08): 회사 로그인 SDK 를 앱에 넣지 않고 **서버가 로그인을 대신 끝내는 방식**이라, 카카오 키 해시·Play 앱 서명 SHA 지문은 **필요 없다**.

## 1. Firebase (https://console.firebase.google.com)

1. **프로젝트 추가** → 이름 `emoti` → 프로젝트 ID 확인(이것이 `<프로젝트ID>`) → Google 애널리틱스 **사용 안 함** → 만들기.
2. 왼쪽 아래 **요금제 › 업그레이드 › Blaze**(사용한 만큼 결제) — 결제 계정 연결.
   - 이어서 **Google Cloud 콘솔 › 결제 › 예산 및 알림 › 예산 만들기**: 이름 `emoti 월 예산`, 금액 예: ₩10,000, 알림 50%·90%·100%. (알림일 뿐 자동으로 멈추지 않는다.)
3. **빌드 › Authentication › 시작하기**. **로그인 방법 › Google › 사용 설정**(관리자 페이지 로그인용) — 지원 이메일 선택 → 저장.
   - **설정 › 승인된 도메인**에 `<프로젝트ID>.web.app` 이 있는지 확인(기본으로 있음).
4. **빌드 › Firestore Database › 데이터베이스 만들기** → 위치 **us-central1** → **프로덕션 모드**로 시작(규칙은 배포 때 덮어씀).
5. **빌드 › Storage › 시작하기** → 위치 **us-central1** → 프로덕션 모드.
6. **프로젝트 설정(톱니) › 일반 › 내 앱 › 웹(</>)** → 앱 닉네임 `emoti-app` → (Hosting 체크 안 해도 됨) → 등록. 나오는 `firebaseConfig` 의 `apiKey · authDomain · projectId · storageBucket · messagingSenderId · appId` 는 **공개 값**이다 — 이 값을 채팅에 붙여 주면 앱 빌드 설정과 관리자 페이지 `config.json` 에 넣는다.
7. **Google Cloud 콘솔 › IAM 및 관리자 › IAM** → `<프로젝트 번호>-compute@developer.gserviceaccount.com` 줄의 연필 → **역할 추가 › 서비스 계정 토큰 생성자(Service Account Token Creator)** → 저장. (서버 함수가 로그인 토큰을 만들 때 필요. 함수를 한 번 배포한 뒤에 이 계정이 보이면 그때 해도 된다.)

**운영자 PC 터미널**(저장소 `server/firebase` 폴더):
```bash
npx firebase login
```
```bash
npx firebase use --add
```
(프로젝트 목록에서 방금 만든 것 선택, 별칭 `prod`)

## 2. 구글 로그인 (https://console.cloud.google.com — 같은 프로젝트 선택)

1. **API 및 서비스 › OAuth 동의 화면**(또는 **Google 인증 플랫폼 › 브랜딩**)
   - 앱 이름 `emoti 이모티`, 사용자 지원 이메일, 개발자 연락처 이메일.
   - 앱 도메인: 홈페이지 `https://<프로젝트ID>.web.app`, 개인정보처리방침 `https://dbs7010-cmd.github.io/emoticon-studio/privacy/`.
   - 사용자 유형 **외부**. 범위(데이터 액세스)는 **추가하지 않음**(앱은 `openid` 만 요청 — 민감 범위 없음, 별도 검수 불필요).
   - 게시 상태 **프로덕션으로 게시**(테스트 상태면 등록한 테스트 사용자만 로그인됨).
2. **API 및 서비스 › 사용자 인증 정보 › + 사용자 인증 정보 만들기 › OAuth 클라이언트 ID**
   - 애플리케이션 유형 **웹 애플리케이션**, 이름 `emoti 로그인 중계`.
   - 승인된 리디렉션 URI: `https://<프로젝트ID>.web.app/auth/callback/google`
   - 만들기 → **클라이언트 ID**(공개 — 채팅으로 줘도 됨) · **클라이언트 보안 비밀번호**(비밀 — 아래 터미널에만).
```bash
npx firebase functions:secrets:set GOOGLE_CLIENT_SECRET
```
(입력 칸에 보안 비밀번호 붙여넣기 — 화면에 보이지 않음)

## 3. 카카오 로그인 (https://developers.kakao.com)

1. **내 애플리케이션 › 애플리케이션 추가하기**: 앱 이름 `emoti 이모티`, 회사명(개인이면 본인 이름), 카테고리 `사진/디자인` 또는 `엔터테인먼트` → 저장.
2. **앱 키 › REST API 키** 복사(공개 취급 가능 — 채팅으로 줘도 됨).
3. **플랫폼 › Web › 사이트 도메인**: `https://<프로젝트ID>.web.app`
   (앱 SDK 를 쓰지 않으므로 Android·iOS 플랫폼 등록은 필요 없다.)
4. **카카오 로그인 › 활성화 설정 ON** → **Redirect URI**: `https://<프로젝트ID>.web.app/auth/callback/kakao`
   (새 콘솔에서는 **앱 › 플랫폼 키 › REST API 키** 화면 안에 리다이렉트 URI 칸이 있다.)
5. **카카오 로그인 › 동의항목**: **아무것도 켜지 않는다**(회원번호는 동의 없이 온다 — 처리방침과 일치). 콘솔이 최소 하나를 요구하면 그 화면을 보내 주면 판단한다.
6. **보안 › Client Secret**(새 콘솔: REST API 키 화면) → 코드 생성 → 활성화 상태 **사용함**.
```bash
npx firebase functions:secrets:set KAKAO_CLIENT_SECRET
```
7. 비즈 앱 전환은 지금 필요 없다(이메일 등 추가 정보를 받지 않음).

## 4. 네이버 로그인 (https://developers.naver.com/apps/#/register)

1. **애플리케이션 등록**: 이름 `emoti 이모티`, 사용 API **네이버 로그인**.
2. 제공 정보 선택: **필수·추가 모두 고르지 않는 것**이 원칙(고유 ID 는 항상 제공). 화면이 최소 하나를 요구하면 **별명** 하나만(앱은 읽지 않음) — 고른 항목을 알려 주면 처리방침을 맞춘다.
3. 로그인 오픈 API 서비스 환경 **PC웹**:
   - 서비스 URL `https://<프로젝트ID>.web.app`
   - 네이버 로그인 Callback URL `https://<프로젝트ID>.web.app/auth/callback/naver`
   (모바일 앱 환경은 SDK 를 쓰지 않으므로 필요 없음.)
4. 등록 → **Client ID**(공개) · **Client Secret**(비밀).
```bash
npx firebase functions:secrets:set NAVER_CLIENT_SECRET
```
5. **검수**: 검수 전에는 **멤버관리**에 등록한 네이버 아이디만 로그인된다. 실기기 검증은 운영자 아이디를 멤버로 넣고 하고, 비공개 테스트 공개 전 **검수 요청**(서비스 화면 캡처 필요 — 첫 실행 화면·로그인 후 홈).

## 5. 서버 배포 (운영자 PC, `server/firebase`)

1. 공개 값 파일 `functions/.env.<프로젝트ID>` — 채팅으로 받은 공개 값으로 **내가 만들어 둔다**(비밀 값 없음, 커밋하지 않음):
```
AUTH_BASE_URL=https://<프로젝트ID>.web.app
GOOGLE_CLIENT_ID=<구글 클라이언트 ID>
KAKAO_REST_KEY=<카카오 REST API 키>
NAVER_CLIENT_ID=<네이버 Client ID>
TRIAL_MAX_DAYS=30
BACKUP_QUOTA_BYTES=1073741824
STALE_UPLOAD_HOURS=24
RETENTION_PRO_LAPSE_DAYS=90
RETENTION_CONTEST_NOT_SELECTED_DAYS=90
RETENTION_CONTEST_SELECTED_DAYS=365
RETENTION_AUTO_DELETE=false
```
2. 관리자 페이지·탈퇴 페이지용 `admin/config.json`(1-6 의 공개 웹 설정) — 내가 만든다.
3. 배포(한 번에):
```bash
npx firebase deploy --only firestore,storage,functions,hosting
```
4. 관리자 권한(운영자 구글 계정으로 관리자 페이지에 한 번 로그인한 뒤 화면에 나오는 uid):
```bash
gcloud auth application-default login
```
```bash
node scripts/set-admin.cjs <프로젝트ID> <관리자 uid>
```

## 6. 앱 빌드 설정
- `EMOTICON_FIREBASE_CONFIG` = 1-6 의 공개 웹 설정 JSON(내가 넣는다)
- `EMOTICON_LOGIN=kakao,naver,google` — **서버에 그 회사 설정을 마친 것만** 켠다(꺼진 회사는 앱에서 '준비 중').
- 이 두 값이 들어간 빌드부터 **로그인 필수**가 실제로 동작한다(서버 설정이 없는 빌드는 지금처럼 로그인 없이 열린다).

## 7. 그다음 검증(실기기 · 실제 서비스)
1. 카카오·네이버·구글 각각 첫 로그인 → 작가명 → 홈 / 재실행 시 로그인 유지
2. 관리자 페이지에서 내 계정에 체험 PRO(기간) → 앱 PRO 백업 → 앱 삭제 없이 **다른 에뮬레이터·기기**에서 같은 계정 로그인 → 복원(재설치 검증은 테스트 기기에서만 — 사용 기기 데이터를 지우지 않는다)
3. 무료 계정으로 공모전 세트 전체 제출 → 관리자 페이지 수신·미리보기·내려받기
4. 웹 `/account/` 에서 테스트 계정 삭제
결과는 '실제 서비스 통과'로, 지금까지의 에뮬레이터·가짜 로그인 통과와 구분해 기록한다.
