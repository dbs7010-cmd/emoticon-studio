## 2. 연결된 출시 빌드에서 확인한 것
- vc9 최종 `dist/emoti-1.0.0-vc9-closedtest-connected-bc678a6.aab`(SHA-256 `d5ec8faa…c6a9da`) 출시 검사 4묶음 PASS — 원장 §51. 앞선 vc9 두 파일(9907cc7·70a8aa0)은 올리지 않는다.
- 에뮬레이터 설치 → **로그인 시작 화면**까지. 로그인 이후는 운영 계정 로그인이 필요해 확인하지 않았다(4번 운영자 작업).

## 3. 자동/에뮬레이터로만 확인한 것
- 자동 41묶음 + 타입 검사 PASS.
- 에뮬레이터(검수 빌드): 위 편의 화면, 저장 → 강제 종료 → 재실행 보존, 덮어 설치 보존, 내보내기 묶음 생성.
- 코드로 찾아 고친 위험: 앱을 막 열어 로그인을 되살리는 동안 시작 재확인이 산 사람의 PRO 를 끌 수 있었음 → 로그인 증명이 생길 때까지 묻지 않음(`iap-test`). 서버 거절 이유('다른 emoti 계정에 연결')가 화면에 보이게 함.
- **내보낸 파일 안쪽은 확인하지 못함**: ① 앱 내부 파일은 출시 서명(디버그 불가)이라 읽을 수 없음(의도된 보호) ② 공유로 꺼낼 대상이 에뮬레이터에 드라이브·Gmail·Nearby·블루투스뿐(계정·다른 기기 필요). 공유를 받아 저장하는 시험용 앱 설치는 권한이 허용되지 않아 하지 않았다. → 운영자 휴대폰에서 4-③으로 확인 필요.

## 4. 운영자가 할 실기기·콘솔 작업 (순서·기대 결과)
자세한 표: 문서 26 §5·§6.
1. **작품 보호 먼저**: 내 정보 › 전체 백업 만들기 → 드라이브 저장.
2. 연결 빌드 화면 확인(설치: Play 업데이트 또는 `dist/emoti-1.0.0-vc9-closedtest-connected-bc678a6-universal.apk` 덮어 설치): 로그인 → '부분' 칩 → 손 흔들기 → '조합' → 저장 → PRO 화면 세 장 → 클라우드 백업(운영 DB `backups/kakao:…/sets` 생김).
3. **내보낸 파일 확인**: 세트 › 내보내기 › 파일 묶음 만들기 → 드라이브(또는 카카오톡 나에게) 저장 → PC 로 받아 주면 ZIP 안 파일 수·360×360·용량·GIF 장 수·움직임을 검사한다.
4. 다른 로그인 확인: 로그아웃 → 구글 로그인 → 작품 보임·백업 'PRO 전용' → 다시 카카오.
5. 구매(청구 없는 방법): Console › 설정 › 라이선스 테스트에 휴대폰 Play 계정 확인 → 결제 열린 빌드(새 vc10 필요)로 테스트 카드 구매 → **같은 화면 구매 복원**(재설치 없이) → 운영 DB `users/{uid}.pro.source=store, sandbox=true`. 재설치 복원은 1번 백업 뒤에만.
6. Console 제출: 게시 개요의 실제 문구 '변경사항이 검토를 위해 전송되지 않음 · 문제 1개 — 계정 세부정보 업데이트: 한국 개발자 추가 정보'. 통신판매업 신고 번호 등을 입력한 뒤 **문제 수가 0 이 되는지 먼저 확인**(바로 열린다고 단정하지 않음). 남아 있으면 그 문구를 알려 주면 다음 조치를 정리한다.
